## 三、本轮补齐的交付契约

1. **`content/docs/_index.zh.md` → `content/docs/_index.md`**（`git mv`）。
   技能 scaffold 判据只认 `content/docs/_index.md`；本站默认语言是 `zh`，两种命名产出的 URL 与页面一致。改名后重新构建仍为 `Pages 1022 / Static files 34`，`public/docs/index.html` 标题不变。
2. **`hugo.yaml` 的 `preset` / `preset_menu` 去掉行尾注释**，注释移到键上方。
   原因：技能判据用 `^\s*preset:\s*(.+?)\s*$` 取值，行尾 `# ...` 会被当成值的一部分，导致 `preset=paper  # 默认观感...` 与计划的 `paper` 比对失败。Hugo 侧行为不变。
3. **`run.cmd` 契约**：`verify_site.check_run_cmd` 返回 `None`（存在、CRLF、离线变量、`NO_OPEN` / `NO_PAUSE` / `--openBrowser` / `SITE_TITLE` 标记齐全）。
4. **`.gitignore`**：`git check-ignore -v` 命中 `public`、`resources`、`_mermaid-harness`；`oink-main`、`content`、`hugo.yaml`、`run.cmd`、`doc` 未被忽略。

### 4.1 nav：脚本误判，站点本身正确

`verify_site.gate_nav` 用非贪婪正则取菜单区：

```python
re.search(r'<div[^>]*td-nav-menu-zone[^>]*>(.*?)</div>', html, re.S)
```

本站顶栏第一项 blog 是带下拉的分组，渲染出嵌套 `<div>`，非贪婪匹配在第一个 `</div>` 就闭合，于是只读到 blog，漏掉后面的 docs 与 book。等深配对读取同一区域的结果：

```text
zone_len=2300 anchors=6 top_level=['./blog/', './docs/', './book/']
docs OK  blog OK  book OK
```

技能自带的 `demo-docs-140`（只有 `./docs/` 一项）与 `demo-gallery-140`（三项都是叶子链接）没有嵌套 div，所以此缺陷在示例包里不显形。这是判据侧问题，未改技能脚本。

### 4.2 links：440 条坏链为克隆自带

`check_links` 按源文件口径统计，440 条坏链按目标前缀分组：

| 前缀 | 条数 |
|------|------|
| `/images/` | 230 |
| `/../` | 79 |
| `/zh/` | 75 |
| `/blog/` | 32 |
| `/operations/` | 21 |
| 其余（`/about/`、`/compatibility/`、`/docs/`） | 3 |

`unmapped=416` 的主因是脚本把 `page.zh.md` 映射成 `page.zh/index.html`，而本站默认语言为 `zh`，产物是 `page/index.html`。这些是克隆源残留与判据口径差异，按本轮约定不改正文。

### 4.3 audit：计划模型与克隆树不兼容

- `content/docs` 下 92 个目录、404 个 Markdown（其中 403 个 `.zh.md`），最深比 `content/docs` 低 4 层；
- 改名后仍有 91 个目录只有 `_index.zh.md`，没有 `_index.md`；
- 技能计划模型是 `docs/<分类>/<板块>/<文件>` 两层目录，且要求每层 `_index.md` 与每篇文章都登记在计划里，无法表达本站的 4 层树与 `.zh.md` 命名。

技能自身也写明：整站复刻既有文档站应使用 `replicate-doc-site`，不适用本技能的计划生成与文体审计。因此 `plan` / `audit` 两项在本仓库记为不适用，而不是内容缺陷。

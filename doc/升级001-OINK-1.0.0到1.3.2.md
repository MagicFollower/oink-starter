## 一、为什么必须换副本，而不是改配置

本站升级前的主题副本是 **1.0.0**，那份副本里「视觉预设」这套东西**根本不存在**——
不是没开，是没有实现文件。所以把 `preset_menu` 写对也不会有任何效果，且**构建一句错都不报**。

| 关键文件 | 1.0.0 副本（升级前） | 1.3.2 副本（升级后） |
|---|---|---|
| `assets/scss/td/_presets.scss` | 不存在 | 存在 |
| `assets/scss/td/_experimental-presets.scss` | 不存在 | 存在 |
| `assets/scss/td/_appearance.scss` | 不存在 | 存在 |
| `layouts/_partials/preset-config.html` | 不存在 | 存在 |

**这条是本次升级唯一的硬前提**，也因此判据不能只看 `hugo.yaml`：配置层全绿而产物层为空，正是旧副本上的静默失效形态。

### 关于那个被停用的自定义覆盖件

它是为绕开 1.0.0 缺陷写的。三个版本的第二循环守卫逐字对照：

```
1.0.0 主题   {{- if .IsSection -}}
站点覆盖     {{- if and .IsSection (ne .Params.sidebar_root_menu false) -}}
1.3.2 主题   {{- if and .IsSection .RelPermalink (not .Params.sidebar_divider) (ne .Params.sidebar_root_menu false) -}}
```

1.3.2 上游**已经吸收**了站点补的那条判断，并多两条守卫。继续留着覆盖 = 主动放弃那两条。
另外实测：本站 100 篇 md 里**没有任何一篇**声明 `sidebar_root_menu: false`，也没用 `sidebar_divider`——
这条覆盖一直在防一个没发生过的缺陷，停用它对本站零行为影响。

## 五、未验证与遗留（都不是本次升级引入的）

1. **ink / terminal 两套预设的实际观感没有人眼核对过**，也没在本副本复跑上游 `bin/check-presets.py`
   （它自称验过 AA 对比度，那是上游脚本的声明）。本站默认已钉 `paper`，两套实验项只是进了读者菜单。
2. **链接面本次未取到可信结论**：技能的 `check_links.py` 报 `links_checked=19 broken=3 unmapped=12`，
   按其自身契约 `unmapped≠0` 时 `broken` 不可信。12 个 UNMAPPED 的成因已查明是**判据缺口而非站点问题**：
   目录名里的空格被 Hugo 归一成连字符（产物实际是 `apache-poi导入解析工具实践一`），
   而脚本推断 URL 时保留了空格。这条要单独修 `check_links.py`，属技能侧缺陷。
3. **3 条 BROKEN 是内容里残留的绝对路径**，与主题版本无关：
   `content/blog/post/本站全局搜索技术栈分析报告.md` 正文里写了 `file:///e:/github/Java-Doc-Site/...` 三条
   （`offline-search-index.json`、`search-engine.js`、`hugo.yaml`），属换机即断的机器路径，建议改成站内相对路径或删除该段。
4. `layouts/_partials/shell/root-menu-entries（侧边栏下拉卡片列表选中置顶效果）.html` 是**死文件**——
   Hugo 按模板名精确解析，带说明性后缀的文件没有任何调用点。未擅自删除，请确认后再处置。
5. `doc/` 内几处链接指向 `问题清单.md`，该文件不在 `doc/` 目录里（既有状况，未动）。

## 六、回滚

工作树在升级前是干净的，全部改动可一次性回退：

```
git checkout -- go.mod go.sum hugo.yaml oink-main layouts/_partials/shell/root-menu-roots.html
git clean -fd oink-main
mv layouts/_partials/shell/root-menu-roots.html.superseded-1.3.2 layouts/_partials/shell/root-menu-roots.html
```

回滚后需重新构建一次（`hugo --cleanDestinationDir`）以清掉 1.3.2 的产物。

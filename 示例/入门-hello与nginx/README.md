## 一、怎么跑（两条命令，顺序不能反）

```bash
cd Docker知识库/示例/入门-hello与nginx
python 入门跑一遍.py --selftest   # 第一步：证明判据会红（五条坏样本必须 5/5）
python 入门跑一遍.py               # 第二步：主流程，读 INTRO_PASS
```

主流程自己也会先跑一遍 `--selftest`，**五条坏样本没全被抓到就拒绝出绿**——这不是客套，
是因为一条永远为真的检查等于没检查。

前置条件只有两条：引擎在跑（`docker version` 有 Server 段），本机有 `nginx:1.27-alpine`
（没有也行，`docker pull` 走的是引擎侧通路，见下面「本机现值」）。

## 二、它会动你的引擎吗

会动，但范围是**一个前缀、两只容器、零个卷**：

| 对象 | 名字 | 处置 |
|---|---|---|
| 一次性容器 | `hello-world`（`--rm`） | 跑完自己就没，脚本另外断言了一次「不留残留」 |
| 长驻容器 | `kb31_intro_web`（nginx） | 脚本内部 `stop` → `rm`，并回读「按名查为空」 |
| 卷 | 无 | 不建卷，所以也不删卷 |
| 端口 | 现挑（`bind` + `netstat` 双查，本轮用过 18901~18903） | 用完就放，不占用别人的号 |
| 网络/配置 | 无 | 不改 daemon 配置、不重启 Desktop、**不跑任何 `prune`** |

**它自己留下的唯一长期痕迹**是 `hello-world:latest` 这个 25.9 kB 的镜像——1.3 的产出物要用，故意保留。

## 四、判据清单（哪格会自己红，靠什么红）

| 编号 | 判据 | 会不会自己红 |
|---|---|---|
| C0 | 开工前 `kb31_intro_web` 不存在 | 会：残留列表里塞一个名字就是坏样本 4 |
| C1/C2 | `hello-world` 退出码 0 且输出含 `Hello from Docker!` | 会：坏样本 1 把标记换成不存在的串 |
| C3 | `--rm` 跑完不留容器 | 会：同 C0 一类（`expect_absent`） |
| C4/C5 | nginx 起得来、`ps` 里状态是 running | 会：端口撞了就 rc≠0 |
| C6 | 就绪探针拿到 `HTTP 200` | 会：坏样本 2 拿一个没人监听的端口 |
| C7 | 访问之后 access log 行数**增加**（`1 → 2`） | 会：坏样本 3 把前后两次喂成同一个数 |
| C8 | 日志里有本次请求的 UA 标记 | 会：标记换成别的串 |
| C9/C9b | 版本行只在 stderr、access log 只在 stdout | 会：坏样本 5 把两个流对调；主流程第一次跑就是在这格红的 |
| C10~C14 | stop 后连不上、状态 `exited`、rm 后按名查为空 | 会：同 C0 一族 |
| C15 | 容器/卷/网络计数回到开工基线 | 会：任何一格没清干净就红 |
| C16 | 浏览器与 curl 看到同一页 | **不会**：脚本没法替你眼；这一格永远标 MANUAL |

## 五、几个读数的出处（免得被当成"常识"）

- **`docker run -it` 在没有终端时**给的是 `cannot attach stdin to a TTY-enabled container because stdin is not a terminal`，不是「成功但没输出」。
- **`nginx/1.27.5` 那行自报版本在 stderr**；只搜 stdout 的判据读不到它（本脚本 C9 第一次就是红的）。
  而 `nginx/` 这个词在 stdout 里也会出现（入口脚本打印 `/etc/nginx/conf.d/default.conf`），
  所以分流判据必须钉在 `nginx/\d+\.\d+` 这个形状上。
- **端口冲突的原文**长这样：`Bind for 127.0.0.1:18501 failed: port is already allocated`，
  而且 `docker run -d` 这时**会打印一个容器 ID 再退出 rc=125**——失败不等于没留下东西。
- **容器日志里的时间是 UTC**：本机墙钟 11:29 对应日志里的 `03:29:02`。
- 更完整的落点与生命周期（这只容器的可写层在哪、删了会带走什么）在正文
  [/docs/10-存储专题/落点与生命周期/容器启动停止与存储的关系/](../../content/docs/10-存储专题/落点与生命周期/容器启动停止与存储的关系.md)。

## 六、想改它

- 换镜像/端口段：只改文件顶部的 `IMAGE_WEB`、`NAME`、`pick_port(start=…)`，**别动判据函数的参数形状**——
  坏样本靠的就是「同一函数喂不同参数」。
- 加一条判据的规矩：先写出它的坏样本，再写主流程那格。写不出坏样本的，就标 MANUAL，别标 PASS。

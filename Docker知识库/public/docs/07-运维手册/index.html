文档 一条主线八站供通读，十个主题篇供查阅；进度、前置与产出物写在每篇开头。 导读 站在入口：双轨怎么读、八站地图、环境准备，以及这个库的写作规矩。 基础认知 先知道容器解决的是什么问题，再亲手跑起第一个容器。 核心操作 主线站①的日常命令面：把容器跑起来、看住它、连上网、留住数据。 镜像构建 主线站③④⑤：从第一份 Dockerfile，到别人也能 build、能拉。 单机编排 主线站②：把九参数的 docker run 变成一条 compose up。 原理深入 按需查阅层：不要求通读，每篇开头的触发条件告诉你什么时候该来。 工程化与生产 团队尚在本地开发阶段，本篇按「上生产前的准入基线 + 演练」写，不假装有生产事故。 运维手册 使用频率最高的一篇，故障域各节一律按「症状 → 判据 → 命令 → 根因」四列写。 生态与附录 坐标与查阅件：什么时候该换工具，以及版本口径以谁为准。 常见问题 压在全库最后：每条按「问题—机制—数字/命令—自查动作」四段作答，并指回正文判据。

# 为什么需要方法引用？

Lambda 让你可以把「一段动作」写成便签。但写到第三天你会发现一个尴尬的现象：**很多便签上的内容，公司标准流程手册里早就有了一字不差的版本**。

```java
// ========== 观察：这些 Lambda 体内，只有对「已有方法」的一次调用 ==========
Function<String, Integer>  f1 = s -> s.length();          // String 已有 length()
Consumer<String>           c1 = s -> System.out.println(s); // System.out 已有 println
Supplier<List<String>>     s1 = () -> new ArrayList<>();  // ArrayList 已有构造器
Predicate<String>          p1 = s -> s.isEmpty();         // String 已有 isEmpty()
```

每条 Lambda 都在**用新便签复述一件旧能力**：参数怎么传、箭头怎么画，全是对已有方法的重复描述。当这些 Lambda 出现在长链式调用的中段，重复的「参数 → 箭头 → 调用」三件套反而稀释了真正重要的信息——**调用的是哪个方法**。

Java 8 的解法：**方法引用（`::` 双冒号语法）**——不写便签，直接把已有的方法本体指给快递单：

```java
// ========== 方法引用：指名道姓，不复述 ==========
Function<String, Integer>  f2 = String::length;
Consumer<String>           c2 = System.out::println;
Supplier<List<String>>     s2 = ArrayList::new;
Predicate<String>          p2 = String::isEmpty;
```

| 对比项 | Lambda 复述版 | 方法引用版 |
|--------|--------------|-----------|
| 写法 | `s -> s.length()` | `String::length` |
| 信息焦点 | 被参数、箭头稀释 | 直接落在方法名上 |
| 意图表达 | 「一段调用某方法的逻辑」 | 「就是那个方法本身」 |
| 出错面 | 需要自己维护参数传递 | 无参数转发环节，无传错参的可能 |

> ### 💡 新人小结：方法引用是什么？
>
> 把方法引用想象成**点熟手**：
> - Lambda 是现场手写操作手册，哪怕操作手册仓库早就有了 —— 复述已有能力
> - 方法引用是直接说「**就按 3 号窗老张的标准流程办**」—— 指名道姓
> - 老张的流程签名必须和快递单匹配 —— 引用的方法签名必须符合目标函数接口
>
> **一句话总结：方法引用 = 当 Lambda 体只是「调一下某个已有方法」时，直接写下那个方法的名字。**

**学习路线图**

```
四种形式 → 类的实例方法引用 → 构造器与数组引用 → this/super → 选型对比 → Q&A
认全双冒号   最易误解的一种     new 也能被引用     特殊场景     何时用哪种   出错怎么办
```

**本文涉及的专有名词**（先解释后使用；SAM、目标类型见《Lambda表达式详解》）：

| 术语 | 全称 | 含义（用自己的话） | 在本文中的角色 |
|------|------|--------------------|----------------|
| 方法引用 | method reference | 用 `类名::方法名` 直接指向一个已有方法的表达式 | 本文主角 |
| 接收者 | receiver | 实例方法调用中「点号前的那个对象」，如 `s.length()` 里的 `s` | 理解第三种引用形式的关键 |
| 重载解析 | overload resolution | 编译器在多个同名方法中按参数类型选定一个 | 解释 `Integer::parseInt` 等重载方法如何被引用 |
| 构造器引用 | constructor reference | 用 `类名::new` 指向构造方法 | 第四种形式，创建对象的行为参数化 |

## 核心概念：四种方法引用形式

| 形式 | 语法 | 等价 Lambda | 快递类比 |
|------|------|------------|---------|
| 1. 静态方法引用 | `类名::静态方法` | `x -> 类名.静态方法(x)` | 总部标准流程：报单号即可办 |
| 2. 对象的实例方法引用 | `实例::方法` | `x -> 实例.方法(x)` | 指定某个窗口：都找这个窗口办 |
| 3. 类的实例方法引用 | `类名::实例方法` | `(obj, x) -> obj.方法(x)` | 岗位标准流程：谁当班谁按流程办 |
| 4. 构造器引用 | `类名::new` | `x -> new 类名(x)` | 空白面单：按参数开新单 |

```java
public class FourForms {
    public static void main(String[] args) {
        // 形式 1：静态方法 —— Integer.parseInt(String)
        Function<String, Integer> parse = Integer::parseInt;
        System.out.println(parse.apply("42"));            // 输出: 42

        // 形式 2：特定对象的实例方法 —— System.out.println(String)
        Consumer<String> announce = System.out::println;
        announce.accept("包裹已到站");                     // 输出: 包裹已到站

        // 形式 3：类的实例方法 —— 第一个参数成为接收者
        Function<String, Integer> len = String::length;   // 等价 s -> s.length()
        System.out.println(len.apply("包裹ABC"));         // 输出: 5

        // 形式 4：构造器 —— 调 new User(String, int)
        BiFunction<String, Integer, User> creator = User::new;
        User u = creator.apply("阿明", 26);
        System.out.println(u.getName());                  // 输出: 阿明
    }
}

class User {
    private final String name;
    private final int age;
    User(String name, int age) { this.name = name; this.age = age; }
    String getName() { return name; }
    int getAge() { return age; }
}
```

**参数解释**：

- 形式 1/2 与普通调用直觉一致：`类名.静态方法`、`实例.方法`。
- 形式 3 的 `类名::实例方法` **并没有**「类调实例方法」这回事——它的等价 Lambda 中，**参数列表的第一个元素充当接收者**。
- 形式 4 的 `new` 没有方法名，就用 `new` 关键字本身占位；目标接口的签名决定匹配哪个构造器。

## 主体内容

### 形式 3 深挖：最容易误解的「类的实例方法引用」

初学者最常卡在第三种形式——明明是实例方法，为什么挂在类名上？拆开看：

```java
// ========== 三个等价写法，逐级简化 ==========
Function<String, Integer> f1 = s -> s.length();   // Lambda：s 是接收者
Function<String, Integer> f2 = (String s) -> s.length();
Function<String, Integer> f3 = String::length;    // 方法引用：隐含「第一个参数当接收者」

// ========== 两个参数时：第一个当接收者，第二个当方法参数 ==========
BiFunction<String, Integer, Boolean> startsWith = String::startsWith;
// 等价：(s, prefix) -> s.startsWith(prefix)
System.out.println(startsWith.apply("华东包裹", "华东"));   // 输出: true
```

**参数解释**：

| Lambda 参数 | 方法引用中去了哪 |
|-------------|-----------------|
| 第 1 个参数 `s` | 变成实例方法的**接收者**（`s.length()` 的 `s.`） |
| 第 2 个及以后的参数 | 依次成为方法的**实参**（`s.startsWith(prefix)` 的 `prefix`） |

记忆模型：`类名::实例方法` 描述的是「**这个类所有对象的同一种标准行为**」——安检员不看具体是谁的包裹，按 String 类的标准流程检查。所以它能放进任何「第一个参数是这个类（或其父类型）」的函数接口格子。

**常见匹配失败**：目标接口的第一个参数不是该类型（或其父类型）时无法匹配，编译器报「不兼容」——这是类型系统的保护，不是语法问题。

```java
// ❌ Function<Integer, Integer> bad = String::length;
//    String::length 需要 String 当接收者，这里给的是 Integer

// ✅ 想转换 Integer 就老实用 Lambda 或静态方法引用
Function<Integer, String> good = n -> "编号" + n;
```

### 构造器引用与数组引用：创建行为也能参数化

```java
// ========== 按目标接口签名匹配构造器 ==========
Supplier<List<String>>  emptyList  = ArrayList::new;            // 匹配无参构造
Function<Integer, List<String>> sizedList = ArrayList::new;     // 匹配 ArrayList(int initialCapacity)

// ========== 工厂场景：创建哪种包裹由参数决定 ==========
static Supplier<Logger> loggerFactory() {
    return Logger::new;   // 想换成 FileLogger 只改这一处 —— 创建逻辑参数化
}

// ========== 数组构造引用：指定长度开新数组 ==========
Function<Integer, String[]> arrayMaker = String[]::new;         // 等价 len -> new String[len]
String[] arr = arrayMaker.apply(3);
System.out.println(arr.length);                                  // 输出: 3
```

**参数解释**：

- 同一个 `ArrayList::new`，放进 `Supplier` 格子就匹配无参构造，放进 `Function<Integer,...>` 格子就匹配带容量构造——**目标类型再次说了算**。
- 数组引用 `类型[]::new` 是构造器引用的特例，接收 int 长度参数。

构造器引用的经典落点是 `Stream.toArray`（官方实践一节演示）与各种工厂/缓存场景，它把「怎么创建对象」变成可传递的策略。

### this 与 super 方法引用

方法引用还能指向**当前类或父类**的方法，在回调场景很实用：

```java
public class OrderPanel {
    void onArrive(String pkg) { System.out.println("到件：" + pkg); }

    void register() {
        // 等价 Lambda：pkg -> this.onArrive(pkg)
        EventQueue.onArrive(this::onArrive);   // this:: 引用当前实例的方法
    }
}

class ExpressPanel extends OrderPanel {
    void register() {
        // super:: 引用父类实现（如先复用父类行为再做增强）
        EventQueue.onArrive(super::onArrive);
    }
}
```

**参数解释**：`this::方法` 与 `super::方法` 都属于形式 2（特定对象的实例方法引用），只是「那个对象」分别是当前实例与父类视角。事件监听、回调注册中 `this::handler` 是最常见的高频写法。

> ### 💡 新人小结：四种形式怎么记？
>
> 按快递场景记四句话：
> - `类::静态方法` —— **总部标准流程**，报单号就办
> - `实例::方法` —— **指定窗口**，只找这个窗口
> - `类::实例方法` —— **岗位标准流程**，第一个参数当班
> - `类::new` / `类型[]::new` —— **空白面单**，按参数开新单
>
> **一句话总结：双冒号左边指「去哪办」，右边指「办什么」，格式由目标函数接口说了算。**

### 演进对比：等价 Lambda vs 方法引用

统一场景：把用户名列表转成长度列表。

**旧方案：Lambda 复述已有方法。**

```java
List<Integer> lengths = users.stream()
        .map(u -> u.getName())          // 只是调 getName，参数转发是噪音
        .map(name -> name.length())     // 只是调 length
        .collect(Collectors.toList());
```

**当前方案：方法引用。**

```java
List<Integer> lengths = users.stream()
        .map(User::getName)             // 直接点名「取名字」
        .map(String::length);           // 直接点名「量长度」
```

**对比分析表**：

| 对比维度 | 旧方案：Lambda 复述 | 当前方案：方法引用 |
|----------|--------------------|--------------------|
| 写法差异 | 重复书写「参数 ->」与参数转发 | 去掉转发层，直接指向方法 |
| 行为差异（重构联动） | 方法改名时 Lambda 体调用同步报错，但**读代码时多一层转译** | 方法改名/删签名时引用处直接报错，意图零转译 |
| 行为差异（表达力） | 可加入包装逻辑、参数改名、多语句 | 只能原样引用，无法夹带任何逻辑 |
| 迁移成本 | — | 团队需掌握四种形式的匹配规则，尤其是形式 3 |
| 旧方案适用场景 | 需要对结果加工（`u -> "用户:" + u.getName()`）、参数需要改名提升可读性、体含多语句 | 逻辑恰好是「调用一个已有方法」时，一律优先方法引用 |

**选型决策树**：

```text
Lambda 体是否只有一次方法调用（或 new）？
    │
    ├─ 否 → 用 Lambda（逻辑复杂，方法引用表达不了）
    │
    └─ 是 → 参数是否被改名/加工后才传入方法？
              │
              ├─ 是 → 用 Lambda（保住可读性）
              │
              └─ 否 → 用方法引用（可读性最好）
```

## 官方 / 社区实践

```java
// ========== 1. Comparator.comparing + 键提取器方法引用 ==========
users.sort(Comparator.comparing(User::getName));                 // 按名字排
users.sort(Comparator.comparing(User::getAge).reversed());       // 按年龄倒序

// ========== 2. Stream.toArray + 数组构造引用（Java 8 收尾惯用法） ==========
String[] arr = names.stream().toArray(String[]::new);

// ========== 3. Map.computeIfAbsent + 构造器引用（多值 Map 惯用法） ==========
Map<Character, List<String>> byInitial = new HashMap<>();
for (String name : names) {
    byInitial.computeIfAbsent(name.charAt(0), k -> new ArrayList<>()).add(name);
    // Supplier 位置也可写 ArrayList::new（无参构造匹配 Supplier）
}

// ========== 4. 集合批量操作 ==========
names.forEach(System.out::println);            // 形式 2 的最高频用法
names.removeIf(Objects::isNull);               // 形式 1：Objects 静态方法
```

**参数解释**：

- `toArray(String[]::new)`：Stream 需要按元素个数创建目标数组，数组引用正好提供「int → 数组」的签名。
- `removeIf(Objects::isNull)`：静态方法引用作为 Predicate 的标准案例，语义自解释「移除为 null 的」。
- `Comparator.comparing(User::getName)`：键提取器 + 方法引用，是 JDK 8 之后排序的第一写法，彻底替代匿名 Comparator。

## 高频问题与踩坑排查（Q&A）

**Q1：方法引用能指向重载方法吗？选哪个由谁决定？**

能。选哪个由**目标函数接口的签名**决定（又是目标类型）：`System.out::println` 放进 `Consumer<String>` 就匹配 `println(String)`，放进 `Consumer<Integer>` 就匹配 `println(int)`（自动装箱）。只有当目标类型也无法消歧时才编译失败。

**Q2：方法引用比 Lambda 性能更好吗？**

基本等价。两者底层都是 `invokedynamic` 运行期生成实现，JIT 后差异可忽略。**选择依据是可读性，不是性能**——为「性能」把 Lambda 改成方法引用属于无效优化。

**Q3：为什么 `list::add` 可以放进 `Predicate`？返回值不是 boolean 吗？**

`list::add` 返回 boolean 没问题；真正有趣的是 `list.forEach(list::add)` 这种把返回值丢弃的匹配——**方法引用（与表达式 Lambda）允许「有返回值但目标接口要求 void」**，返回值被静默丢弃。这叫 void 兼容。

**Q4：方法引用的方法签名和接口差一个参数能匹配吗？**

不能。签名必须严格匹配（参数个数、类型、返回值兼容）。匹配不上时不要硬凹引用形式，回退 Lambda——方法引用是「恰好指得上」时的优化表达，不是万能缩写。

**Q5：`String::length` 报错「无法解析」一般是什么原因？**

最常见两类：目标接口第一个参数不是 String 或其父类型（形式 3 匹配失败）；导错了同名类。先检查目标格子签名，再检查 import。

---

**Q6：`System.out::println` 属于哪种形式？`Arrays::sort` 呢？**

`System.out::println` 是**形式 2**（特定对象的实例方法引用）——`System.out` 本身是一个确定的实例（字段表达式），引用挂在这个实例上。`Arrays::sort` 是**形式 1**（静态方法引用）。判别口诀：冒号左边是**类名且方法是静态** → 形式 1；左边是**类名且方法是实例方法** → 形式 3；左边是**能求出一个具体对象的表达式** → 形式 2。

**Q7：方法引用可以像链一样接着写吗？比如 `String::length::toString`？**

不能。`::` 不是可串联的运算符，它只是「指向某个方法」的记号。要对引用结果二次加工，走函数组合的正路：用 `andThen` 组合两个引用，或退回 Lambda：

```java
Function<String, String> lenToStr = String::length.andThen(String::valueOf);
System.out.println(lenToStr.apply("包裹ABC"));   // 输出: 5
```

**方法引用匹配失败的四步排查**：

1. 先看**目标接口**的抽象方法签名（参数个数、类型、返回值）——一切由它说了算；
2. 判断引用属于哪种**形式**（静态 / 对象实例 / 类实例 / 构造器）；
3. 按该形式的规则核对参数去向：形式 3 检查「第一个参数当接收者」的类型，构造器引用检查对应签名的构造器是否存在；
4. 仍匹配不上，回退等价 Lambda——引用是「恰好指得上」时的奖励，不是必选项。

**四形式 × 等价 Lambda 速查**：

| 例子 | 形式 | 等价 Lambda |
|------|------|------------|
| `Integer::parseInt` | 1 静态方法 | `s -> Integer.parseInt(s)` |
| `System.out::println` | 2 对象的实例方法 | `s -> System.out.println(s)` |
| `String::startsWith` | 3 类的实例方法 | `(s, p) -> s.startsWith(p)` |
| `ArrayList::new` | 4 构造器 | `() -> new ArrayList<>()` |

## 要点总结

1. **方法引用四种形式**：静态 `类::方法`、实例 `实例::方法`、类实例方法 `类::方法`、构造器 `类::new`（含 `类型[]::new`）。
2. **形式 3 的秘密**：第一个参数当接收者，其余参数当实参——`String::startsWith` 等价 `(s, p) -> s.startsWith(p)`。
3. **目标类型再次说了算**：同一个 `ArrayList::new` 因格子不同匹配不同构造器；重载方法也由目标类型消歧。
4. **选型看内容**：体只是单次调用（或 new）→ 方法引用；需要加工、改名、多语句 → Lambda。
5. **性能无差别**：两者同为 invokedynamic 机制，方法引用的价值在可读性与意图表达。

> ### 💡 新人小结：方法引用学完了，记住这 3 点
>
> 1. **能点熟手就不手写手册** —— Lambda 体只有一次调用时，换成 `::` 引用
> 2. **岗位流程（形式 3）第一个参数当班** —— 别被「类名调实例方法」的表象骗到
> 3. **格式永远由快递单（目标类型）决定** —— 同一个引用，换个格子匹配另一套签名
>
> **一句话总结：方法引用把「复述已有能力」压缩成「指名道姓」，链式代码从此一眼看到重点。**

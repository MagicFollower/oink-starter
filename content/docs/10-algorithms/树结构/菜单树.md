# 为什么需要菜单树？

打开你的电脑文件管理器，左侧的目录树就是「树形结构」：

```
📁 文档
  📁 工作
    📄 报告.pdf
    📄 方案.docx
  📁 学习
    📄 笔记.md
```

但在数据库中，这些信息是「平铺」存储的：

| id | name | parent_id |
|----|------|----------|
| 1 | 文档 | 0 |
| 2 | 工作 | 1 |
| 3 | 报告.pdf | 2 |
| 4 | 方案.docx | 2 |
| 5 | 学习 | 1 |
| 6 | 笔记.md | 5 |

**核心问题**：如何把「平铺列表」转换成「树形结构」？

> ### 💡 新人小结：平铺 vs 树形
>
> 想象你在整理通讯录：
> - **平铺**：每个人只记录「我的上级是谁」→ 像一张表格
> - **树形**：每个人下面挂着「我的下属」→ 像组织架构
>
> 菜单树就是把「表格」变成「组织架构图」的过程。

**学习路线图**：

```
数据模型 → 方案一：递归法 → 方案二：HashMap → 对比与选型
TreeNode  直观但 O(n²)   优化到 O(n)    何时用哪个？
```

## 问题场景

前端菜单、组织架构、商品分类等场景中，数据库存储的是**平铺的父子关系列表**（每条记录只有 id 和 parentId），但前端展示需要**树形嵌套结构**。

**输入**（平铺列表）：

| id | pid | title |
|----|-----|-------|
| 1 | 0 | 系统管理 |
| 11 | 1 | 用户管理 |
| 2 | 0 | 数据管理 |
| 22 | 2 | 报表查看 |
| 221 | 22 | 月度报表 |

**输出**（树形结构）：

```
├── 系统管理 (id=1)
│   └── 用户管理 (id=11)
└── 数据管理 (id=2)
    └── 报表查看 (id=22)
        └── 月度报表 (id=221)
```

## TreeNode 数据模型

```java
public class TreeNode {
    private Long id;
    private Long pid;
    private String title;
    private List<TreeNode> children = new ArrayList<>();

    public TreeNode() {}

    public TreeNode(Long id, Long pid, String title) {
        this.id = id;
        this.pid = pid;
        this.title = title;
    }

    // getter / setter 省略
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public Long getPid() { return pid; }
    public void setPid(Long pid) { this.pid = pid; }
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    public List<TreeNode> getChildren() { return children; }
    public void setChildren(List<TreeNode> children) { this.children = children; }
}
```

## 方案一：递归构建法

### 痛点引入

最直观的思路：先找顶层节点，然后对每个顶层节点找它的子节点，再对每个子节点找它的子节点……递归下去。

遍历列表找出所有顶层节点（pid = rootId），然后对每个顶层节点递归查找其子节点。

```java
public class TreeBuilder {

    /**
     * 将平铺列表构建为树形结构
     *
     * @param nodes 平铺节点列表
     * @param rootPid 顶层节点的父 ID（通常为 0 或 null）
     * @return 树形结构的根节点列表
     */
    public static List<TreeNode> buildTree(List<TreeNode> nodes, Long rootPid) {
        if (rootPid == null || nodes == null || nodes.isEmpty()) {
            return new ArrayList<>();
        }
        List<TreeNode> tree = new ArrayList<>();
        for (TreeNode node : nodes) {
            if (Objects.equals(rootPid, node.getPid())) {
                tree.add(node);
                buildChildren(node, nodes);
            }
        }
        return tree;
    }

    private static void buildChildren(TreeNode node, List<TreeNode> nodes) {
        if (node == null || nodes == null || nodes.isEmpty()) return;
        List<TreeNode> children = new ArrayList<>();
        for (TreeNode child : nodes) {
            if (Objects.equals(node.getId(), child.getPid())) {
                children.add(child);
            }
        }
        if (!children.isEmpty()) {
            node.setChildren(children);
            for (TreeNode child : children) {
                buildChildren(child, nodes);
            }
        }
    }
}
```

### 复杂度分析

- **时间复杂度**：O(n²) — 每个节点都要遍历整个列表查找子节点
- **空间复杂度**：O(n) — 存储树结构

当节点数较多（> 1000）时，性能较差。

## 方案二：HashMap 预处理法（推荐）

### 痛点引入

递归法的问题：每个节点都要遍历整个列表找子节点，1000 个节点就要查 100 万次。

**优化思路**：先用 HashMap 把所有节点按 id 存起来，查找子节点时直接从 Map 里取——O(1) 而不是 O(n)。

先用一次遍历将所有节点按 id 放入 HashMap，再用一次遍历建立父子关系。

```java
public class TreeBuilderOptimized {

    /**
     * O(n) 构建：HashMap 预处理 + 一次遍历建立父子关系
     *
     * @param nodes 平铺节点列表
     * @param rootPid 顶层节点的父 ID
     * @return 树形结构的根节点列表
     */
    public static List<TreeNode> buildTree(List<TreeNode> nodes, Long rootPid) {
        if (rootPid == null || nodes == null || nodes.isEmpty()) {
            return new ArrayList<>();
        }

        // 第一步：将所有节点按 id 放入 HashMap
        Map<Long, TreeNode> map = new HashMap<>(nodes.size());
        for (TreeNode node : nodes) {
            node.setChildren(new ArrayList<>());  // 初始化 children
            map.put(node.getId(), node);
        }

        // 第二步：一次遍历，建立父子关系
        List<TreeNode> tree = new ArrayList<>();
        for (TreeNode node : nodes) {
            if (Objects.equals(rootPid, node.getPid())) {
                // 顶层节点
                tree.add(node);
            } else {
                // 非顶层节点，找到其父节点并挂载
                TreeNode parent = map.get(node.getPid());
                if (parent != null) {
                    parent.getChildren().add(node);
                }
            }
        }
        return tree;
    }
}
```

### 复杂度分析

- **时间复杂度**：O(n) — 两次线性遍历
- **空间复杂度**：O(n) — HashMap 存储

## 两种方案对比

| 对比项 | 递归构建法 | HashMap 预处理法 |
|--------|-----------|----------------|
| 时间复杂度 | O(n²) | O(n) |
| 空间复杂度 | O(n) | O(n) |
| 实现难度 | 简单直观 | 稍复杂 |
| 适用场景 | 节点数 < 500 | 节点数 > 500 |
| 保持原始顺序 | 是 | 是 |

## 完整测试

```java
public static void main(String[] args) {
    List<TreeNode> nodes = new ArrayList<>();
    nodes.add(new TreeNode(1L, 0L, "系统管理"));
    nodes.add(new TreeNode(11L, 1L, "用户管理"));
    nodes.add(new TreeNode(2L, 0L, "数据管理"));
    nodes.add(new TreeNode(22L, 2L, "报表查看"));
    nodes.add(new TreeNode(221L, 22L, "月度报表"));

    // 方案一
    List<TreeNode> tree1 = TreeBuilder.buildTree(nodes, 0L);
    printTree(tree1, "");

    // 方案二
    // 重新创建节点（方案一已修改了 children）
    List<TreeNode> nodes2 = new ArrayList<>();
    nodes2.add(new TreeNode(1L, 0L, "系统管理"));
    nodes2.add(new TreeNode(11L, 1L, "用户管理"));
    nodes2.add(new TreeNode(2L, 0L, "数据管理"));
    nodes2.add(new TreeNode(22L, 2L, "报表查看"));
    nodes2.add(new TreeNode(221L, 22L, "月度报表"));

    List<TreeNode> tree2 = TreeBuilderOptimized.buildTree(nodes2, 0L);
    printTree(tree2, "");
}

private static void printTree(List<TreeNode> nodes, String indent) {
    for (TreeNode node : nodes) {
        System.out.println(indent + node.getTitle() + " (id=" + node.getId() + ")");
        if (node.getChildren() != null && !node.getChildren().isEmpty()) {
            printTree(node.getChildren(), indent + "    ");
        }
    }
}
```

**输出**：

```
系统管理 (id=1)
    用户管理 (id=11)
数据管理 (id=2)
    报表查看 (id=22)
        月度报表 (id=221)
```

# 要点总结

1. **核心问题**：平铺列表（id + pid）→ 嵌套树形结构
2. **递归法**直观但 O(n²)，适合小规模数据
3. **HashMap 法** O(n)，是工程实践中的首选方案
4. **rootPid 的选择**：通常为 0 或 null，表示顶层节点的父 ID
5. **children 初始化**：建树前应确保每个节点的 children 已初始化为空列表，避免 null 指针

## 为什么需要「高阶」排序？

在基本排序中我们看到，比较排序的极限是 O(n log n)。但现实中有三种场景迫使我们寻找更强的方案：

| 场景 | 痛点 | 解法 |
|------|------|------|
| 对 10 亿个手机号排序 | 快排/归并也要 O(n log n)，常数很大 | 基数排序：按位分桶，接近 O(n) |
| 对均匀分布的考试成绩排序 | 数据范围已知且集中 | 桶排序：分桶后桶内排序 |
| 需要保证 O(n log n) 且不能用额外空间 | 归并需要 O(n) 空间 | 堆排序：原地、始终 O(n log n) |

> **一句话总结**：高阶排序不是「更难的简单排序」，而是三种完全不同的算法思想——**按位分配**、**分桶处理**、**堆数据结构**。它们各自代表了算法设计中「跳出比较排序框架」的三条路径。

---

## 概述

本文介绍三种进阶排序算法，各自代表不同的算法思想：

| 算法 | 类型 | 核心思想 | 平均时间复杂度 | 稳定性 |
|------|------|----------|---------------|--------|
| 基数排序 | 非比较排序 | 按位分配到桶 | O(d · (n + k)) | ✔️ 稳定 |
| 桶排序 | 非比较排序 | 分桶 + 桶内排序 | O(n + k) | 取决于桶内算法 |
| 堆排序 | 比较排序 | 堆数据结构 | O(n log n) | ❌ 不稳定 |

> ### 💡 新人小结：「不比较」也能排序？
>
> 前面学的排序都是「比较排序」——两个元素比大小来决定顺序。但想象一下邮局分拣信件：先按省份分到不同大区，再按城市分到不同袋子，最后按街道分到具体地址。每一步都没有「比较大小」，而是根据信息的某一位直接归类——这就是基数排序的思想。
>
> 同样，桶排序就像把不同分数段的学生分到不同教室，然后每个教室内部再排序。堆排序则利用了一种特殊的树形结构（堆），每次都能快速找到最大值。

## 一、基数排序（Radix Sort）

### 核心思想

按位分配到桶。从最低位（LSD）或最高位（MSD）开始，将每个数字按当前位的值放入 0~9 号桶中，然后按桶顺序收集回数组，重复直到处理完最高位。

### 算法步骤

1. 找出数组最大值，确定最大位数 `d`
2. 初始化 10 个桶（对应数字 0~9）
3. 从最低位开始，对每一位执行：
   - 将每个元素按当前位的数字放入对应桶
   - 按桶顺序依次取回元素
   - 清空桶
4. 处理完最高位后，排序完成

### 位提取方法

基数排序需要逐位提取数字。有两种常用方式：

```java
// 方式一：数学运算（推荐，效率高）
int digit = (num / (int) Math.pow(10, i)) % 10;  // 提取第 i 位（从 0 开始）

// 方式二：字符串转换（直观但效率低）
char c = String.valueOf(num).charAt(len - 1 - i);
int digit = c - '0';
```

> 方式一通过 `÷ 10^i` 将目标位移到个位，再 `% 10` 取出。例如 `num=1234, i=2`：`1234 / 100 = 12`，`12 % 10 = 2`。

### Java 实现

```java
import java.util.ArrayList;
import java.util.List;

public static void radixSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;

    // 1. 找最大值，确定位数
    int max = arr[0];
    for (int v : arr) if (v > max) max = v;

    // 2. 初始化 10 个桶
    @SuppressWarnings("unchecked")
    List<Integer>[] buckets = new ArrayList[10];
    for (int i = 0; i < 10; i++) buckets[i] = new ArrayList<>();

    // 3. 从低位到高位，逐位分配收集
    for (int exp = 1; max / exp > 0; exp *= 10) {
        // 分配到桶
        for (int num : arr) {
            buckets[(num / exp) % 10].add(num);
        }
        // 收集回数组
        int idx = 0;
        for (List<Integer> bucket : buckets) {
            for (int num : bucket) {
                arr[idx++] = num;
            }
            bucket.clear();
        }
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(d·(n+k)) | O(d·(n+k)) | O(d·(n+k)) | O(n+k) | ✔️ 稳定 |

> `d` = 最大位数，`k` = 基数（十进制为 10）。当 `d` 和 `k` 为常数时，时间复杂度为 O(n)。

### 支持负数的改进

原始实现仅支持非负整数。处理负数的策略：**正负分离，分别排序，负数倒序拼接**。

```java
public static void radixSortSigned(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    List<Integer> negatives = new ArrayList<>();
    List<Integer> positives = new ArrayList<>();
    for (int v : arr) {
        (v < 0 ? negatives : positives).add(v < 0 ? -v : v);
    }
    radixSort(toArray(negatives));   // 正数部分基数排序
    radixSort(toArray(positives));
    // 负数取反后倒序（绝对值大的负数更小），拼接正数部分
    int idx = 0;
    for (int i = negatives.size() - 1; i >= 0; i--) arr[idx++] = -negatives.get(i);
    for (int v : positives) arr[idx++] = v;
}
```

### 要点

- 非比较排序，不受 O(n log n) 下界限制
- 适合整数排序，对浮点数需要额外转换
- 位数 `d` 较小时效率极高
- 是 LSD（Least Significant Digit）方案，从低位到高位

## 二、桶排序（Bucket Sort）

### 核心思想

将值域分为若干等宽区间（桶），把元素分配到对应桶中，每个桶内部单独排序，最后按桶顺序收集。

### 与基数排序的区别

| 对比 | 基数排序 | 桶排序 |
|------|---------|--------|
| 分桶依据 | 每一位的值（0~9） | 值域范围 |
| 桶数量 | 固定 10 个（十进制） | 根据数据范围计算 |
| 桶内排序 | 不需要（按序收集即可） | 需要（桶内可能无序） |
| 适用数据 | 整数 | 任意可比较数据 |

### 稳定性说明

桶排序的稳定性**取决于桶内排序算法**：

- 桶内使用插入排序 / 归并排序 → 整体**稳定**
- 桶内使用快速排序 → 整体**不稳定**
- JDK 中 `Collections.sort()` 使用 TimSort（稳定），因此桶内调用 `Collections.sort()` 可保证稳定性

### 算法步骤

1. 找出最大值 `max` 和最小值 `min`
2. 计算桶数量：`bucketCount = (max - min) / n + 1`
3. 初始化桶
4. 将元素分配到桶：`bucketIndex = (num - min) / n`
5. 对每个桶内部排序
6. 按桶顺序收集

### Java 实现

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public static void bucketSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;

    // 1. 找最大值和最小值
    int max = arr[0], min = arr[0];
    for (int v : arr) {
        if (v > max) max = v;
        if (v < min) min = v;
    }

    // 2. 初始化桶（桶数 = 值域 / 数据量 + 1）
    int bucketCount = (max - min) / n + 1;
    List<List<Integer>> buckets = new ArrayList<>(bucketCount);
    for (int i = 0; i < bucketCount; i++) buckets.add(new ArrayList<>());

    // 3. 分配元素到桶
    for (int num : arr) {
        buckets.get((num - min) / n).add(num);
    }

    // 4. 桶内排序（Collections.sort 使用 TimSort，稳定）
    for (List<Integer> bucket : buckets) {
        Collections.sort(bucket);
    }

    // 5. 收集回原数组
    int idx = 0;
    for (List<Integer> bucket : buckets) {
        for (int num : bucket) {
            arr[idx++] = num;
        }
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n) | O(n + k) | O(n²) | O(n + k) | 取决于桶内排序 |

> `k` 为桶数量。最好情况：元素均匀分布，每桶 O(1)。最坏情况：所有元素落入同一桶，退化为桶内排序算法的复杂度。

### 要点

- 适合**均匀分布**的数据
- 可用于**外部排序**——数据量超过内存时，分桶后逐桶加载处理
- 桶内排序算法可灵活替换
- 自然支持负数（通过 `min` 偏移）

## 三、堆排序（Heap Sort）

### 痛点引入

快速排序最坏会退化到 O(n²)，归并排序需要 O(n) 额外空间。有没有一种排序，**始终** O(n log n) 且只需要 O(1) 额外空间？

堆排序就是答案。它利用一种叫做「堆」的树形数据结构，每次都能快速找到最大值，放到正确位置。

> ### 💡 新人小结：堆排序的生活类比
>
> 想象一场淘汰赛：每个选手和另外两个选手比，胜者晋级。最终冠军站在最上面——这就是「堆顶」。把冠军请出去（放到数组末尾），让剩下的人重新比一次，又会产生新的冠军。重复这个过程，所有选手就按名次排好了。
>
> 「堆」就像一棵树，父节点总是比子节点大（最大堆）。用数组表示时，父节点 i 的左孩子是 2i+1，右孩子是 2i+2——不需要指针，纯数组就能表达树的关系。

### 核心思想

利用**最大堆**数据结构。堆顶是最大值，将其与末尾交换后，对剩余元素重新调整堆，重复直到全部有序。

### 堆的性质

堆是一棵**完全二叉树**，用数组表示时满足：

| 关系 | 公式 |
|------|------|
| 父节点 `i` 的左子节点 | `2i + 1` |
| 父节点 `i` 的右子节点 | `2i + 2` |
| 子节点 `i` 的父节点 | `(i - 1) / 2` |

**最大堆**：每个节点 ≥ 其子节点。堆顶 `arr[0]` 为最大值。

### 算法步骤

1. **建堆**：从最后一个非叶子节点 `n/2 - 1` 开始，逆序对每个节点执行 `heapify`
2. **排序**：将堆顶（最大值）与末尾交换，堆大小减 1，对新堆顶执行 `heapify`
3. 重复步骤 2 直到堆大小为 1

### Java 实现

```java
public static void heapSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;

    // 1. 建堆：从最后一个非叶子节点开始，逆序 heapify
    for (int i = n / 2 - 1; i >= 0; i--) {
        heapify(arr, n, i);
    }

    // 2. 依次取出堆顶（最大值），放到末尾
    for (int i = n - 1; i > 0; i--) {
        int tmp = arr[0];
        arr[0] = arr[i];
        arr[i] = tmp;
        heapify(arr, i, 0); // 对缩小后的堆执行 heapify
    }
}

/**
 * 调整以 i 为根的子树，使其满足最大堆性质。
 *
 * @param arr    数组
 * @param heapSize 当前堆的有效大小
 * @param i      当前节点索引
 */
private static void heapify(int[] arr, int heapSize, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < heapSize && arr[left] > arr[largest]) {
        largest = left;
    }
    if (right < heapSize && arr[right] > arr[largest]) {
        largest = right;
    }
    if (largest != i) {
        int tmp = arr[i];
        arr[i] = arr[largest];
        arr[largest] = tmp;
        heapify(arr, heapSize, largest); // 递归调整受影响的子树
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ 不稳定 |

> 建堆过程为 O(n)（非 O(n log n)），排序阶段为 O(n log n)。总体 O(n log n)。

### 为什么最后一个非叶子节点是 `n/2 - 1`？

完全二叉树中，叶子节点集中在最后两层。对于 `n` 个节点的完全二叉树：

- 最后一个节点索引为 `n - 1`
- 其父节点索引为 `(n - 1 - 1) / 2 = n/2 - 1`
- 这就是最后一个非叶子节点

> 例如 `n = 8`：最后一个非叶子节点为 `8/2 - 1 = 3`。节点 3 的子节点为 7 和 8（索引），其中 7 是最后一个有效索引。

### 要点

- 时间复杂度**始终** O(n log n)，无最坏情况退化
- 原地排序，空间 O(1)——优于归并排序
- 不稳定：堆调整过程中可能改变相同元素的相对位置
- 适合**Top-K 问题**：只需前 K 个最大/最小元素时，用堆（优先队列）比全排序高效
- JDK 中的 `PriorityQueue` 就是基于堆实现

## 总对比

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定性 | 适用场景 |
|------|------|------|------|------|--------|----------|
| 基数排序 | O(d·(n+k)) | O(d·(n+k)) | O(d·(n+k)) | O(n+k) | ✔️ | 整数 / 位数少 |
| 桶排序 | O(n) | O(n+k) | O(n²) | O(n+k) | 可选 | 均匀分布数据 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ | 保证 O(n log n) / Top-K |

### 三种算法的选型决策树

```
需要排序的数据是什么类型？
│
├─ 整数，且位数 d 较小 ──→ 基数排序（接近 O(n)，极快）
│
├─ 均匀分布的浮点数 ──→ 桶排序（利用分布特性）
│
└─ 通用数据 ──→ 需要什么保证？
    │
    ├─ 需要 O(n log n) + O(1) 空间 ──→ 堆排序
    ├─ 需要稳定性 ──→ 归并排序（见基本排序）
    └─ 需要通用最快 ──→ 快速排序（见基本排序）
```

## 要点总结

1. **基数排序**：对整数排序极快（接近 O(n)），但不适用于浮点数——核心思想是「按位分配」
2. **桶排序**：利用数据分布特性，均匀分布时接近 O(n)；桶内排序算法可灵活选择
3. **堆排序**：唯一同时满足 O(n log n) 时间保证和 O(1) 空间的比较排序——但常数因子较大，实际不如快排
4. **与基本排序的关系**：堆排序 + 基本排序中的快排/归并，构成了 O(n log n) 比较排序的三大支柱
5. **JDK 的实际选择**：`PriorityQueue` 基于堆；`Arrays.sort()` 不使用堆排序（因为不稳定且常数因子较大）

> ### 💡 新人小结：学完高阶排序后你应该带走什么？
>
> 1. **不是所有排序都要「比大小」**——基数排序和桶排序用「分配」代替「比较」，突破了 O(n log n) 下界
> 2. **堆是一种「会自我调整」的数据结构**——每次取出最大值后，剩余元素能迅速重新组织
> 3. **没有万能算法**——基数排序快但有局限，堆排序稳定但不如快排实际，桶排序依赖数据分布
> 4. **Top-K 问题是堆的主场**——只需要前 K 个最大/最小元素时，用堆比全排序高效得多

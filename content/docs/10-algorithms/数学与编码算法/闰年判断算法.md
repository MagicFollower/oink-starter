# 为什么需要闰年？

你有没有想过：为什么日历不是每年固定 365 天？

因为地球绕太阳转一圈的实际时间不是 365 天，而是约 **365.2425 天**。如果不管它，每过 4 年就会差约 1 天。100 年后，你的日历会和实际季节差 24 天——春节可能跑到夏天去！

**闰年就是「日历的误差修正机制」**。

**学习路线图**：

```
闰年规则 → 两种等价写法 → 位运算优化 → 天文背景
三句话记牢  代码实现      JDK也这么写  为什么这样定
```

> ### 💡 新人小结：为什么闰年规则这么「奇怪」？
>
> 把地球公转想象成一台「不太准的钟」：
> - 它转一圈是 365.2425 天，不是整数
> - 四年一闰：补回 0.25 × 4 = 1 天（但补多了 0.0075 × 4 = 0.03 天）
> - 百年不闰：扣回多补的（但扣多了 0.0025 × 4 = 0.01 天）
> - 四百年再闰：再微调回来
>
> 就像调音：先粗调，再微调，再精调——三次调整后，误差只有 26 秒/年。

## 闰年规则

公历（格里高利历）的闰年规则可以概括为三句话：

1. **四年一闰**：能被 4 整除的年份是闰年
2. **百年不闰**：能被 100 整除的年份不是闰年
3. **四百年再闰**：能被 400 整除的年份又是闰年

| 年份 | 被 4 整除 | 被 100 整除 | 被 400 整除 | 是否闰年 |
|------|----------|-----------|-----------|---------|
| 1996 | ✓ | ✗ | ✗ | **是** |
| 1900 | ✓ | ✓ | ✗ | **否** |
| 2000 | ✓ | ✓ | ✓ | **是** |
| 2024 | ✓ | ✗ | ✗ | **是** |
| 2023 | ✗ | ✗ | ✗ | **否** |

## 两种等价写法

### 痛点引入

闰年规则很简单（三句话），但写成代码时很容易出错——尤其是「百年不闰」和「四百年再闰」的嵌套逻辑。

下面是两种等价的代码写法，理解它们的区别有助于掌握逻辑表达式的短路行为。

### 写法一：先判断整除 4

```java
boolean isLeap = (y % 4 == 0) && (y % 100 != 0 || y % 400 == 0);
```

逻辑：先确认能被 4 整除，再排除整百年（除非也能被 400 整除）。

### 写法二：先判断整除 400

```java
boolean isLeap = (y % 400 == 0) || (y % 4 == 0 && y % 100 != 0);
```

逻辑：先确认能被 400 整除（短路），再处理普通情况。

**两种写法完全等价**，区别在于短路行为：

- 写法一：大部分年份在 `y % 4 == 0` 就短路为 false（75% 的年份）
- 写法二：大部分年份在 `y % 400 == 0` 就短路为 false（99.75% 的年份），然后 `y % 4 == 0` 再过滤

### 运算符优先级

`&&` 的优先级高于 `||`，所以：

```java
y % 400 == 0 || y % 4 == 0 && y % 100 != 0
// 等价于：
(y % 400 == 0) || ((y % 4 == 0) && (y % 100 != 0))
```

## 位运算优化

`y % 4 == 0` 可以用位运算替代：

```java
boolean isLeap = (y & 3) == 0 && (y % 100 != 0 || y % 400 == 0);
```

**原理**：`y & 3` 取 y 的最低 2 位，等价于 `y % 4`。当结果为 0 时，说明能被 4 整除。

| y | y % 4 | y & 3 |
|---|-------|-------|
| 2024 | 0 | 0 |
| 2023 | 3 | 3 |
| 2000 | 0 | 0 |
| 1900 | 0 | 0 |

> 位运算优化在早期硬件上效果明显，现代 JVM 会自动做此类优化，实际性能差异可忽略。

## 完整实现

```java
public class LeapYear {

    /**
     * 判断是否为闰年（写法一）
     */
    public static boolean isLeap1(int y) {
        return (y % 4 == 0) && (y % 100 != 0 || y % 400 == 0);
    }

    /**
     * 判断是否为闰年（写法二）
     */
    public static boolean isLeap2(int y) {
        return (y % 400 == 0) || (y % 4 == 0 && y % 100 != 0);
    }

    /**
     * 判断是否为闰年（位运算优化）
     */
    public static boolean isLeap3(int y) {
        return (y & 3) == 0 && (y % 100 != 0 || y % 400 == 0);
    }

    // ========== 测试 ==========
    public static void main(String[] args) {
        int[] testYears = {1900, 1996, 2000, 2023, 2024, 2100, 2400};
        for (int y : testYears) {
            System.out.printf("%d: %s%n", y, isLeap1(y) ? "闰年" : "平年");
        }
    }
}
```

**输出**：

```
1900: 平年
1996: 闰年
2000: 闰年
2023: 平年
2024: 闰年
2100: 平年
2400: 闰年
```

## 365.2425 天的天文背景

地球绕太阳公转一周的实际时间（回归年）约为 **365.2425 天**：

| 近似 | 规则 | 误差 |
|------|------|------|
| 365 天 | 不做任何闰年处理 | 每年差 0.2425 天，约 4 年差 1 天 |
| 365.25 天 | 每 4 年一闰 | 每年多 0.0075 天，约 128 年差 1 天 |
| **365.2425 天** | **4 年一闰 + 百年不闰 + 四百年再闰** | **每年多 0.0003 天，约 3300 年差 1 天** |

格里高利历的闰年规则使得平均年长为：

```
365 + 1/4 - 1/100 + 1/400 = 365 + 0.25 - 0.01 + 0.0025 = 365.2425 天
```

与实际回归年仅差约 26 秒。

## JDK 参考

`java.time.Year.isLeap()` 的实现与上述逻辑一致：

```java
import java.time.Year;

System.out.println(Year.isLeap(2024));  // true
System.out.println(Year.isLeap(1900));  // false
System.out.println(Year.isLeap(2000));  // true
```

JDK 源码中的实现（简化）：

```java
// java.time.Year 中的核心逻辑
public static boolean isLeap(long year) {
    return ((year & 3) == 0) && ((year % 100) != 0 || (year % 400) == 0);
}
```

可以看到 JDK 使用了位运算优化 `(year & 3) == 0` 替代 `year % 4 == 0`。

## 历史 Bug 案例

### 痛点引入

闰年判断是编程中最容易出 Bug 的算法之一。即使是知名公司的产品，也曾在这里翻车。

| 案例 | 问题 |
|------|------|
| 只判断 `y % 4 == 0` | 1900 年被错误判断为闰年 |
| 忽略 `y % 400 == 0` | 2000 年被错误判断为平年 |
| 优先级错误 | `y % 4 == 0 && y % 100 != 0 \|\| y % 400 == 0` 由于 `&&` 优先级高于 `\|\|`，实际等价于 `(y%4==0 && y%100!=0) \|\| y%400==0`，结果正确但可读性差 |
| OpenAI 2023 年 Bug | ChatGPT 的日期相关功能在闰年判断上出错 |

# 要点总结

1. **三句话规则**：四年一闰、百年不闰、四百年再闰
2. **两种等价写法**：先判断 4 或先判断 400，逻辑完全等价
3. **位运算优化**：`(y & 3) == 0` 替代 `y % 4 == 0`，JDK 也采用此写法
4. **天文背景**：365.2425 天的回归年决定了闰年规则
5. **易错点**：整百年（1900/2100）不是闰年，但 2000/2400 是闰年——这是最常见的测试盲区

> ### 💡 新人小结：闰年判断学完了，记住这 3 点
>
> 1. **规则**：能被 4 整除且不能被 100 整除，或者能被 400 整除
> 2. **代码**：`(y % 4 == 0) && (y % 100 != 0 || y % 400 == 0)` 这一行就够了
> 3. **测试用例**：一定要测 1900（平年）、2000（闰年）、2024（闰年）、2023（平年）——这四个覆盖了所有分支

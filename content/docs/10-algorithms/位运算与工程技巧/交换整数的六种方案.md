# 为什么需要了解交换方案？

交换两个变量，是编程中最「看似简单」的操作之一。

想象你和朋友交换手中的卡片：最自然的方式是「找张桌子先放一张」（临时变量）。但你有没有想过：
- 如果**没有桌子**（不允许额外空间）怎么办？
- 如果你们拿的是**魔法卡片**（异或运算），有一种「咒语」能让卡片自动交换？
- 如果卡片上的数字**太大**（加法溢出），交换会出错？

**本文的六种方案，本质是在探讨一个问题**：在「空间」「安全」「可读性」三个维度上，最优解是什么？

> ### 💡 新人小结：为什么要学「不实用」的方案？
>
> 就像学武术不只是为了打扜，学异或交换不只是为了交换。
> 它能帮你理解：
> - **异或运算的自反性**（a ^ b ^ b = a）——这是加密算法的基础
> - **溢出风险**——为什么 int 相加可能变成负数
> - **工程取舍**——为什么「简单安全」往往比「炫技」更重要

## 概述

交换两个变量是最基础的编程操作。除了最常见的临时变量法，还有异或、加减等多种写法，每种方案有不同的原理和注意事项。

---

## 方案一：临时变量（推荐）

最标准、最安全的写法。

```java
int t = arr[a];
arr[a] = arr[b];
arr[b] = t;
```

- **优点**：无溢出风险，无索引问题，编译器可优化
- **缺点**：需要一个额外变量
- **工程建议**：**绝大多数场景的首选**

---

## 方案二：Stack 辅助

利用栈的后进先出特性完成交换。

```java
Stack<Integer> stack = new Stack<>();
stack.push(arr[a]);
stack.push(arr[b]);
arr[a] = stack.pop();  // 原 arr[b]
arr[b] = stack.pop();  // 原 arr[a]
```

- **优点**：展示了栈的 LIFO 特性
- **缺点**：创建对象开销大，纯属炫技，无工程价值
- **工程建议**：仅作为思维拓展

---

## 方案三：异或交换（写法 A）

利用异或运算的自反性：`x ^ y ^ y = x`。

> ### 💡 新人小结：异或交换的「魔法」原理
>
> 想象你有一个保险箱，里面放着 A 和 B 两件宝物：
> 1. 第一步：把 A 和 B 「混合」在一起（A = A ^ B）
> 2. 第二步：用混合物还原出 B（混合物 ^ 原 B = 原 A）
> 3. 第三步：用混合物还原出 A（混合物 ^ 原 A = 原 B）
>
> 异或就像一种「魔法混合」：两个东西混在一起后，还能分别还原出来。

```java
arr[a] = arr[a] ^ arr[b];
arr[b] = arr[a] ^ arr[b];  // (a^b) ^ b = a
arr[a] = arr[a] ^ arr[b];  // (a^b) ^ a = b
```

### 致命陷阱：同一索引交换导致归零

当 `a == b` 时（即交换同一个位置），第一步 `arr[a] = arr[a] ^ arr[a] = 0`，数据被销毁。

**案例**：在堆排序中，如果 `heapSort` 的交换逻辑中 `a` 和 `b` 可能相同（例如最大值恰好在待交换位置），使用异或交换会导致该位置数据归零。

**修复方案**：在交换前加索引相等判断：

```java
if (a != b) {
    arr[a] = arr[a] ^ arr[b];
    arr[b] = arr[a] ^ arr[b];
    arr[a] = arr[a] ^ arr[b];
}
```

---

## 方案四：异或交换（写法 B — 单行表达式）

利用 Java 赋值表达式的求值顺序，将三步合并为一行：

```java
arr[a] = arr[a] ^ arr[b] ^ (arr[b] = arr[a]);
```

**执行过程**：
1. 先计算右侧：`arr[b] = arr[a]`（赋值给 `arr[b]`，表达式值为原 `arr[a]`）
2. 然后：`arr[a] ^ arr[b] ^ 原arr[a]` = `arr[a] ^ 原arr[b] ^ 原arr[a]` = `原arr[b]`

- **优点**：代码极简
- **缺点**：可读性差，同样存在同一索引归零问题
- **工程建议**：不推荐，可读性远低于方案一

---

## 方案五：加减交换（写法 A）

利用加减法的可逆性：

```java
arr[a] = arr[a] + arr[b];
arr[b] = arr[a] - arr[b];  // (a+b) - b = a
arr[a] = arr[a] - arr[b];  // (a+b) - a = b
```

### 溢出风险

当 `arr[a] + arr[b]` 超过 `Integer.MAX_VALUE`（2147483647）时，会发生整数溢出，导致结果错误。

**示例**：

```java
int a = 2000000000;
int b = 2000000000;
a = a + b;  // 溢出！结果为负数
```

---

## 方案六：加减交换（写法 B — 单行表达式）

```java
arr[a] = arr[a] + arr[b] - (arr[b] = arr[a]);
```

与方案四类似，利用赋值表达式的求值顺序合并为一行。同样存在溢出风险。

---

## 六种方案对比

| 方案 | 额外空间 | 溢出风险 | 同索引安全 | 可读性 | 工程推荐 |
|------|---------|---------|-----------|--------|---------|
| A. 临时变量 | 1 个变量 | 无 | 安全 | 高 | **强烈推荐** |
| B. Stack | O(1) 对象 | 无 | 安全 | 中 | 不推荐 |
| C1. 异或（三行） | 无 | 无 | **不安全** | 低 | 特定场景可用 |
| C2. 异或（单行） | 无 | 无 | **不安全** | 极低 | 不推荐 |
| D1. 加减（三行） | 无 | **有** | 安全 | 低 | 不推荐 |
| D2. 加减（单行） | 无 | **有** | 安全 | 极低 | 不推荐 |

## 完整测试

```java
public static void main(String[] args) {
    // 方案 A：临时变量
    int[] arr1 = {10, 20};
    int t = arr1[0]; arr1[0] = arr1[1]; arr1[1] = t;
    System.out.println("方案A: " + arr1[0] + ", " + arr1[1]);  // 20, 10

    // 方案 C1：异或交换
    int[] arr2 = {10, 20};
    arr2[0] = arr2[0] ^ arr2[1];
    arr2[1] = arr2[0] ^ arr2[1];
    arr2[0] = arr2[0] ^ arr2[1];
    System.out.println("方案C1: " + arr2[0] + ", " + arr2[1]);  // 20, 10

    // 方案 C1 陷阱：同索引交换
    int[] arr3 = {42};
    arr3[0] = arr3[0] ^ arr3[0];  // 42 ^ 42 = 0
    System.out.println("陷阱: " + arr3[0]);  // 0

    // 方案 D1：加减交换
    int[] arr4 = {10, 20};
    arr4[0] = arr4[0] + arr4[1];
    arr4[1] = arr4[0] - arr4[1];
    arr4[0] = arr4[0] - arr4[1];
    System.out.println("方案D1: " + arr4[0] + ", " + arr4[1]);  // 20, 10
}
```

# 要点总结

1. **临时变量法**是工程实践中的唯一推荐方案——安全、高效、可读
2. **异或交换**无溢出风险但有同索引归零陷阱，在堆排序等算法中需要特别注意
3. **加减交换**有溢出风险，在实际工程中应避免
4. **单行表达式**虽然简洁，但牺牲了可读性，不符合工程规范
5. 面试中可以作为考点展示对位运算的理解，但实际编码应优先选择临时变量法

---

> ### 💡 新人小结：交换方案学完了，记住这 3 条结论
>
> 1. **实际编码永远用临时变量**——面试官问起来，先说临时变量，再展示异或
> 2. **异或交换的致命陷阱**：`a == b` 时数据归零，在排序算法中可能触发
> 3. **加减交换有溢出风险**：两个大正数相加可能变成负数，这是 Java 的 int 特性

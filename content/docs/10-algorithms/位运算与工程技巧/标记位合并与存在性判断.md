# 为什么需要位标记？

想象你家的墙上有 **8 个灯开关**，每个开关只有「开」和「关」两种状态。

- **方案 A**：用 8 个 `boolean` 变量分别记录 → 清晰但占空间
- **方案 B**：用一个 **8 位二进制数** 表示所有灯的状态 → `10110010` 表示第 1、4、5、7 号灯开着

位标记就是方案 B 的思想：**用一个整数的每个 bit 位来表示一个独立的布尔状态**。

**实际应用场景**：

| 场景 | 位标记的用法 |
|------|-------------|
| Java 修饰符 | `public static final` → 3 个 bit 位组合成一个 int |
| Linux 文件权限 | `rwxr-xr--` → 9 个 bit 位表示读写执行权限 |
| 游戏状态 | 角色是否中毒/冰冻/眩晕 → 3 个 bit 位 |
| 权限控制 | 读/写/执行/删除 → 4 个 bit 位 |

> ### 💡 新人小结：什么是位标记？
>
> 把 int 的 32 个 bit 位想象成 **32 个开关**：
> - 每个开关只有「开」(1) 和「关」(0) 两种状态
> - 一个 int 就能同时记录 32 个开关的状态
> - 位运算就是操作这些开关的「遥控器」
>
> 就像你家的配电箱：一个开关控制一个房间的灯，位运算就是那个总控面板。

## 核心思想

一个 `int` 有 32 个 bit 位，每个 bit 可以表示一个独立的布尔标记。通过位运算，可以在一个整数中同时存储和操作多达 32 个布尔状态。

| 运算 | 操作 | 示例 |
|------|------|------|
| 或 `\|` | 合并标记（置 1） | `tag \| (1 << 3)` |
| 与 `&` | 检测标记（是否置位） | `(tag & (1 << 3)) != 0` |
| 与取反 `& ~` | 清除标记（置 0） | `tag & ~(1 << 3)` |
| 异或 `^` | 翻转标记 | `tag ^ (1 << 3)` |

## 基本用法

```java
public class BitFlagDemo {
    public static void main(String[] args) {
        int tag = 0;  // 初始状态：所有标记位均为 0

        // 合并标记
        tag = tag | (1 << 3);   // 设置第 3 位
        tag = tag | (1 << 2);   // 设置第 2 位
        System.out.println(Integer.toBinaryString(tag));  // 1100

        // 检测标记
        System.out.println((tag & (1 << 2)) != 0);  // true（第 2 位存在）
        System.out.println((tag & (1 << 3)) != 0);  // true（第 3 位存在）
        System.out.println((tag & (1 << 4)) != 0);  // false（第 4 位不存在）

        // 清除标记
        tag = tag & ~(1 << 3);  // 清除第 3 位
        System.out.println(Integer.toBinaryString(tag));  // 100
        System.out.println((tag & (1 << 3)) != 0);  // false

        // 翻转标记
        tag = tag ^ (1 << 2);   // 翻转第 2 位（1 → 0）
        System.out.println(Integer.toBinaryString(tag));  // 0
        tag = tag ^ (1 << 2);   // 再翻转（0 → 1）
        System.out.println(Integer.toBinaryString(tag));  // 100
    }
}
```

## 完整位操作工具方法

```java
public class BitFlags {

    /** 设置标记位（置 1） */
    public static int set(int flags, int bit) {
        return flags | (1 << bit);
    }

    /** 清除标记位（置 0） */
    public static int clear(int flags, int bit) {
        return flags & ~(1 << bit);
    }

    /** 检测标记位是否为 1 */
    public static boolean test(int flags, int bit) {
        return (flags & (1 << bit)) != 0;
    }

    /** 翻转标记位 */
    public static int toggle(int flags, int bit) {
        return flags ^ (1 << bit);
    }

    // ========== 测试 ==========
    public static void main(String[] args) {
        int flags = 0;

        // 设置多个标记
        flags = set(flags, 0);   // 标记 A
        flags = set(flags, 2);   // 标记 C
        flags = set(flags, 4);   // 标记 E
        System.out.println("flags = " + Integer.toBinaryString(flags));  // 10101

        // 检测
        System.out.println("A(0): " + test(flags, 0));  // true
        System.out.println("B(1): " + test(flags, 1));  // false
        System.out.println("C(2): " + test(flags, 2));  // true

        // 清除
        flags = clear(flags, 2);
        System.out.println("clear C: " + Integer.toBinaryString(flags));  // 10001

        // 翻转
        flags = toggle(flags, 1);
        System.out.println("toggle B: " + Integer.toBinaryString(flags));  // 10011
    }
}
```

## 与 JDK java.lang.reflect.Modifier 的关联

### 痛点引入

你可能已经用过 `public static final` 这些修饰符，但有没有想过：JDK 是怎么存储一个方法的「所有修饰符」的？

答案就是位标记！

JDK 中的 `java.lang.reflect.Modifier` 类正是使用位标记来表示类/方法/字段的修饰符：

```java
// Modifier 中的常量定义
public static final int PUBLIC       = 0x0001;    // bit 0
public static final int PRIVATE      = 0x0002;    // bit 1
public static final int PROTECTED    = 0x0004;    // bit 2
public static final int STATIC       = 0x0008;    // bit 3
public static final int FINAL        = 0x0010;    // bit 4
public static final int ABSTRACT     = 0x0400;    // bit 10
// ...

// 检测修饰符
public static boolean isPublic(int mod) {
    return (mod & PUBLIC) != 0;
}
```

一个方法可以同时是 `public static final`：

```java
int mod = Modifier.PUBLIC | Modifier.STATIC | Modifier.FINAL;
System.out.println(Modifier.isPublic(mod));   // true
System.out.println(Modifier.isStatic(mod));   // true
System.out.println(Modifier.isFinal(mod));    // true
System.out.println(Modifier.isAbstract(mod)); // false
```

## 与 EnumSet 的对比

### 痛点引入

位标记虽然高效，但 `0x0014` 这样的数字可读性太差。JDK 提供了 `EnumSet`——**用枚举的方式实现位标记**，既有位运算的性能，又有良好的可读性。

`EnumSet` 是 JDK 提供的基于位运算的枚举集合实现：

```java
enum Color { RED, GREEN, BLUE }

// EnumSet 内部使用 long 位向量
EnumSet<Color> set = EnumSet.of(Color.RED, Color.BLUE);
System.out.println(set.contains(Color.RED));    // true
System.out.println(set.contains(Color.GREEN));  // false
```

| 对比项 | 位标记 (int) | EnumSet |
|--------|-------------|---------|
| 容量 | 最多 32 个标记（int）或 64 个（long） | 最多 64 个枚举常量 |
| 可读性 | 低（需要理解位运算） | 高（标准集合 API） |
| 类型安全 | 弱（int 无类型约束） | 强（泛型约束） |
| 性能 | 极高（单条 CPU 指令） | 极高（内部也是位运算） |
| 适用场景 | 标志位组合、权限控制、状态压缩 | 枚举集合操作 |

## 优缺点与注意事项

**优点**：
- 空间效率极高：32 个布尔值压缩为 1 个 int（4 字节）
- 运算效率极高：位操作是 CPU 原生指令
- 适合状态压缩、权限控制、标志位组合

**缺点**：
- 可读性差：`0x0014` 不如 `{READ, WRITE}` 直观
- 容量有限：int 最多 32 个标记，long 最多 64 个
- 调试困难：打印出来是数字而非有意义的名称

**注意事项**：
- `1 << bit` 中 bit 的范围：0 ~ 31（int）或 0 ~ 63（long）
- 位运算优先级低于比较运算，务必加括号：`(flags & (1 << bit)) != 0`
- 不要混淆 `&` 和 `&&`：前者是位运算，后者是逻辑运算

# 要点总结

1. **一个 int 的 32 个 bit 位 = 32 个布尔标记**，这是最紧凑的状态存储方式
2. **四种基本操作**：set（或）、test（与）、clear（与取反）、toggle（异或）
3. JDK 的 `Modifier` 类和 `EnumSet` 都是位标记思想的工程实践
4. 适用于权限控制（如 Linux 的 `rwx` 权限）、状态压缩、配置标志等场景
5. 超过 64 个标记时应改用 `BitSet` 或 `boolean[]`

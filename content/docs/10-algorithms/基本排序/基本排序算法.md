## 为什么需要排序？

想象你走进一家图书馆——所有书都是随机摆放的。你想找一本《算法导论》，只能一本一本地翻看，可能翻遍整个图书馆才能找到。现在想象另一种场景：所有书按编号排列，你只需要几秒就能定位到目标。

**这就是排序的价值**：将无序数据变为有序，从而让后续的查找、统计、去重等操作从「大海捞针」变成「按图索骥」。

在实际开发中，排序几乎无处不在：

| 场景 | 排序的作用 |
|------|----------|
| 数据库查询 `ORDER BY` | 结果集按指定列排序后返回 |
| 二分查找 | 前提条件——数组必须有序 |
| 去重 | 排序后相邻元素比较即可去重 |
| 合并有序列表 | 归并排序的核心操作 |
| Top-K 问题 | 部分排序即可获取最大/最小的 K 个元素 |

> **一句话总结**：排序是算法世界的「基础设施」。理解了排序，就掌握了算法分析的起点——时间复杂度、稳定性、分治思想等核心概念都将由此展开。

## 概述

本文涵盖 7 种经典排序算法，按时间复杂度分为两类。学习路线建议：先理解 O(n²) 的三种简单排序（建立直觉），再学习希尔排序（理解「增量」思想），然后攻克快排和归并（掌握分治），最后了解计数排序（突破比较排序下界）。

| 类别 | 算法 | 平均时间复杂度 | 稳定性 |
|------|------|---------------|--------|
| 简单排序 | 选择排序、冒泡排序、插入排序 | O(n²) | 选择排序不稳定，其余稳定 |
| 改进排序 | 希尔排序 | O(n^1.3) ~ O(n²) | 不稳定 |
| 高效排序 | 快速排序、归并排序 | O(n log n) | 快排不稳定，归并稳定 |
| 非比较排序 | 计数排序 | O(n + k) | 稳定 |

> **稳定性**：相同元素排序后相对位置不变。例如数组中有两个 `5`，排序后它们的先后顺序与排序前一致。

> ### 💡 新人小结：什么是时间复杂度？
>
> 把算法想象成一台洗衣机。衣服数量（n）越多，洗的时间越长。时间复杂度描述的就是「衣服数量增长时，洗衣时间如何增长」：
>
> - **O(n²)**：衣服数量翻倍，时间变成 4 倍——像让每件衣服都和其他所有衣服比较一次
> - **O(n log n)**：衣服数量翻倍，时间大约翻倍再多一点——像把衣服分成两堆分别洗，再合并
> - **O(n)**：衣服数量翻倍，时间也刚好翻倍——最理想的情况
>
> 记住这个直觉，后面每学一个排序算法，回来对照一下就能快速理解它的效率等级。

## 一、选择排序（Selection Sort）

### 痛点引入

假设你是一老师，要让班上 n 个学生按身高从矮到高排成一列。你采用的策略是：每次从所有人中找出最矮的那个，让他站到队伍最前面；然后从剩下的人中再找最矮的，让他站第二个位置……重复这个过程直到所有人都排好。

这就是选择排序的核心思路——**每次从无序部分「选出」最小值，放到有序部分的末尾**。

### 核心思想

每次从未排序部分选出最小元素，放到已排序部分末尾。

### 算法步骤

1. 从 `arr[0]` 到 `arr[n-2]`，遍历每个位置 `i`
2. 假设 `i` 为最小值索引 `minIdx`
3. 扫描 `i+1` 到 `n-1`，找到更小的元素则更新 `minIdx`
4. 若 `minIdx != i`，交换两者

### Java 实现

```java
public static void selectionSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        if (minIdx != i) {
            int tmp = arr[i];
            arr[i] = arr[minIdx];
            arr[minIdx] = tmp;
        }
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n²) | O(n²) | O(n²) | O(1) | ❌ 不稳定 |

> **不稳定示例**：`[5, 5, 2]` → 第一轮将 `2` 与第一个 `5` 交换 → `[2, 5, 5]`，两个 `5` 的相对顺序改变。

### 要点

- 交换次数最少，最多 n-1 次，适合**写入成本高**的场景
- 无法利用数据已有规律提前终止

## 二、冒泡排序（Bubble Sort）

### 核心思想

重复遍历数组，比较相邻元素，将较大元素逐步"冒泡"到末尾。

### 算法步骤

1. 从 `j=0` 遍历到 `n-2-i`，比较 `arr[j]` 与 `arr[j+1]`
2. 若 `arr[j] > arr[j+1]`，交换两者
3. 每轮结束后，末尾位置已排好
4. **提前终止优化**：若某轮没有发生任何交换，说明已有序，直接返回

### Java 实现

```java
public static void bubbleSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int tmp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) return; // 已有序，提前终止
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n) | O(n²) | O(n²) | O(1) | ✔️ 稳定 |

### 要点

- 最好情况 O(n) 得益于提前终止优化，适用于**近乎有序**的数据
- 实现最简单的排序算法之一
- 实际工程中很少使用，但常用于教学中引入排序概念

## 三、插入排序（Insertion Sort）

### 核心思想

将数组分为"已排序"和"未排序"两部分，每次取未排序元素插入到已排序部分的正确位置——类似整理手中的扑克牌。

### 算法步骤

1. 从 `i=1` 开始（`arr[0]` 视为已排序）
2. 保存 `key = arr[i]`
3. 从 `i-1` 向前扫描，将大于 `key` 的元素后移
4. 找到合适位置后放入 `key`

### Java 实现

```java
public static void insertionSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n) | O(n²) | O(n²) | O(1) | ✔️ 稳定 |

### 要点

- **近乎有序**的数据效率极高，接近 O(n)
- 小规模数据（n < 50）性能优于快排和归并——JDK 的 `Arrays.sort()` 在子数组小于 47 时切换为插入排序
- 是希尔排序和 TimSort 的基础

## 四、希尔排序（Shell Sort）

### 核心思想

插入排序的改进版。设定递减的增量 `gap`，对每个分组执行插入排序。当 `gap` 缩至 1 时，数组已近乎有序，最后一轮插入排序极快完成。

### 算法步骤

1. 初始 `gap = n / 2`
2. 按 `gap` 分组，对每组执行插入排序
3. `gap = gap / 2`，重复步骤 2
4. 直到 `gap = 1`，执行最后一次插入排序

### Java 实现

```java
public static void shellSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;
    for (int gap = n / 2; gap > 0; gap /= 2) {
        for (int i = gap; i < n; i++) {
            int key = arr[i];
            int j = i - gap;
            while (j >= 0 && arr[j] > key) {
                arr[j + gap] = arr[j];
                j -= gap;
            }
            arr[j + gap] = key;
        }
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n log n) | O(n^1.3) | O(n²) | O(1) | ❌ 不稳定 |

> 增量序列影响复杂度。本文使用 `⌊N/2⌋` 序列（Shell 原始方案），实现简单但非最优。更优序列包括 Knuth 序列 `⌊N/3⌋+1` 和 Sedgewick 序列。

### 要点

- 通过让元素**大步前进、小步微调**，突破 O(n²) 限制
- 原地排序，无需额外空间
- 中等规模数据表现良好，代码简洁

## 五、计数排序（Counting Sort）

### 核心思想

非比较排序。利用数组下标统计每个值出现的次数，再按计数写回。适用于**值范围较小的整数**排序。

### 算法步骤

1. 找出最大值 `max`
2. 创建计数数组 `count[max + 1]`
3. 遍历原数组，`count[arr[i]]++`
4. 按 `count` 数组顺序写回原数组

### Java 实现

```java
public static void countingSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    int n = arr.length;
    int max = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] > max) max = arr[i];
    }
    int[] count = new int[max + 1];
    for (int i = 0; i < n; i++) {
        count[arr[i]]++;
    }
    int idx = 0;
    for (int i = 0; i <= max; i++) {
        while (count[i]-- > 0) {
            arr[idx++] = i;
        }
    }
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n + k) | O(n + k) | O(n + k) | O(k) | ✔️ 稳定 |

> `k` 为值域范围（最大值）。当 `k = O(n)` 时，时间复杂度为 O(n)。

### 支持负数的改进版

原始版本要求所有元素为非负整数。使用 `TreeMap` 可支持任意整数，利用其**自然排序**特性按序输出：

```java
import java.util.Map;
import java.util.TreeMap;

public static void countingSortV2(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    TreeMap<Integer, Integer> map = new TreeMap<>();
    for (int v : arr) {
        map.merge(v, 1, Integer::sum);
    }
    int idx = 0;
    for (Map.Entry<Integer, Integer> e : map.entrySet()) {
        int count = e.getValue();
        while (count-- > 0) {
            arr[idx++] = e.getKey();
        }
    }
}
```

> 改进版时间复杂度为 O(n log n)（TreeMap 插入为 O(log n)），空间 O(n)。适用于需要支持负数且代码简洁优先的场景。

## 六、快速排序（Quick Sort）

### 痛点引入

O(n²) 的排序在面对大规模数据时太慢了。能不能像「分而治之」那样，把一个大问题拆成两个小问题分别解决？

快速排序正是这个思路：随便选一个「基准值」，把比它小的放左边、比它大的放右边——这样基准值就到了最终正确的位置。然后对左右两半分别重复同样的操作，直到所有元素都到位。

> ### 💡 新人小结：快速排序的生活类比
>
> 想象你要整理一副扑克牌。你随手抽一张牌作为「基准」，然后把所有比它小的牌放左边，比它大的放右边。此时这张基准牌已经在它最终该在的位置了。接着对左边那堆和右边那堆分别重复同样的操作。几轮下来，整副牌就有序了。
>
> 这就是**分治思想**：把一个大问题拆成两个规模减半的子问题，分别解决后，大问题自然也就解决了。

### 核心思想

分治策略。选取基准值（pivot），将数组分为两部分：小于 pivot 的放左边，大于 pivot 的放右边，然后递归处理两部分。

### 算法步骤

1. 选取 `arr[high]` 作为基准值（Lomuto 分区方案）
2. 用指针 `i` 追踪"小于区"的右边界
3. 遍历 `j` 从 `low` 到 `high-1`：若 `arr[j] < pivot`，交换到小于区
4. 将 pivot 放到正确位置（`i` 的下一个）
5. 递归处理左右两部分

### Java 实现

```java
public static void quickSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    quickSort(arr, 0, arr.length - 1);
}

private static void quickSort(int[] arr, int low, int high) {
    if (low < high) {
        int pivotIndex = partition(arr, low, high);
        quickSort(arr, low, pivotIndex - 1);
        quickSort(arr, pivotIndex + 1, high);
    }
}

private static int partition(int[] arr, int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] < pivot) {
            i++;
            int tmp = arr[i];
            arr[i] = arr[j];
            arr[j] = tmp;
        }
    }
    int tmp = arr[i + 1];
    arr[i + 1] = arr[high];
    arr[high] = tmp;
    return i + 1;
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n log n) | O(n log n) | O(n²) | O(log n) | ❌ 不稳定 |

### 关键优化

| 优化 | 说明 |
|------|------|
| 三数取中 | 取 `arr[low]`、`arr[mid]`、`arr[high]` 的中位数作为 pivot，避免最坏情况 |
| 小数组切换插入排序 | 子数组长度 < 16 时改用插入排序，减少递归开销 |
| 尾递归优化 | 对较小的递归分区使用迭代而非递归 |
| 三向切分 | 对大量重复元素，将数组分为 `< pivot`、`== pivot`、`> pivot` 三部分，显著减少比较次数 |

> **JDK 实现**：`Arrays.sort()` 对基本类型使用 **Dual-Pivot Quicksort**（双轴快排），由 Vladimir Yaroslavskiy 提出，平均性能优于传统单轴快排。

## 七、归并排序（Merge Sort）

### 痛点引入

快速排序虽然快，但有一个问题：最坏情况下会退化到 O(n²)。有没有一种排序算法，**无论数据长什么样**，都能保证 O(n log n)？

归并排序就是这样的算法。它的思路极其优雅：如果两堆牌各自已经排好了序，那么把它们合并成一堆有序牌，只需要依次比较两堆的牌顶，取较小的那张——就像两条有序队列合并成一条。

> ### 💡 新人小结：归并排序的生活类比
>
> 想象你有两叠已经按大小排好的扑克牌。你要把它们合成一叠。怎么做？只需要每次从两叠的顶部各拿一张，比较大小，把较小的放到新叠里。重复这个过程，很快就能合并完成。
>
> 那怎么让每叠牌先各自有序呢？递归地做同样的事——把每叠再拆成两小叠，直到每叠只有 1 张牌（1 张牌自然是有序的），然后逐层合并回去。

### 核心思想

分治策略。将数组不断二分直到单个元素，然后将有序子数组合并为更大的有序数组。合并操作是核心。

### 算法步骤

1. 计算中点 `mid`，将数组分为左右两半
2. 递归排序左半部分和右半部分
3. 使用辅助数组将两个有序部分合并

### Java 实现

```java
public static void mergeSort(int[] arr) {
    if (arr == null || arr.length <= 1) return;
    mergeSort(arr, new int[arr.length], 0, arr.length - 1);
}

private static void mergeSort(int[] arr, int[] tmp, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2; // 防溢出
    mergeSort(arr, tmp, left, mid);
    mergeSort(arr, tmp, mid + 1, right);
    merge(arr, tmp, left, mid, right);
}

private static void merge(int[] arr, int[] tmp, int left, int mid, int right) {
    int i = left, j = mid + 1, k = left;
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) {
            tmp[k++] = arr[i++];
        } else {
            tmp[k++] = arr[j++];
        }
    }
    while (i <= mid) tmp[k++] = arr[i++];
    while (j <= right) tmp[k++] = arr[j++];
    System.arraycopy(tmp, left, arr, left, right - left + 1);
}
```

### 复杂度分析

| 最好 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| O(n log n) | O(n log n) | O(n log n) | O(n) | ✔️ 稳定 |

> `merge` 中 `arr[i] <= arr[j]` 的 `=` 保证了稳定性——相等时优先取左侧元素。

### 要点

- 唯一时间复杂度**始终**为 O(n log n) 的比较排序
- 需要 O(n) 额外空间，不适合内存受限场景
- 是**链表排序**的最佳选择（链表归并无需额外空间）
- 是外部排序（数据量超过内存）的标准算法

> **JDK 实现**：`Arrays.sort()` 对对象类型使用 **TimSort**——基于归并排序与插入排序的混合算法，能利用数据中的已有有序片段。

## 辅助技巧

### 中点计算防溢出

归并排序中计算中点 `mid = (low + high) / 2`，当 `low` 和 `high` 都很大时，`low + high` 可能溢出为负数。

| 方案 | 代码 | 说明 |
|------|------|------|
| 直接除 | `(low + high) / 2` | ❌ 可能溢出 |
| 减法 | `low + (high - low) / 2` | ✔️ 安全 |
| 无符号右移 | `(low + high) >>> 1` | ✔️ 最优，JDK 源码采用 |

```java
// 溢出验证
int low = 2147483647;  // Integer.MAX_VALUE
int high = 2147483647;
System.out.println((low + high) / 2);        // -1（溢出！）
System.out.println(low + (high - low) / 2);  // 2147483647
System.out.println((low + high) >>> 1);      // 2147483647
```

### 合并两个有序数组

归并排序核心操作的直接应用——双指针依次比较，与 `merge` 方法逻辑一致：

```java
public static int[] mergeSortedArrays(int[] a, int[] b) {
    int[] result = new int[a.length + b.length];
    int i = 0, j = 0, k = 0;
    while (i < a.length && j < b.length) {
        if (a[i] <= b[j]) {
            result[k++] = a[i++];
        } else {
            result[k++] = b[j++];
        }
    }
    while (i < a.length) result[k++] = a[i++];
    while (j < b.length) result[k++] = b[j++];
    return result;
}
```

| 插入排序 | O(n) | O(n²) | O(n²) | O(1) | ✔️ | 小数组 / 近乎有序 |
| 希尔排序 | O(n log n) | O(n^1.3) | O(n²) | O(1) | ❌ | 中等规模 |
| 计数排序 | O(n+k) | O(n+k) | O(n+k) | O(k) | ✔️ | 整数 / 值域小 |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) | ❌ | **通用最快** |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | ✔️ | 需稳定性 / 链表 |

### 排序算法演进路线图

```
O(n²) 简单排序                O(n log n) 高效排序           O(n) 非比较排序
┌─────────────────┐          ┌──────────────────┐         ┌────────────┐
│ 选择 → 冒泡 → 插入 │ ──→    │  快排    归并排序  │ ──→     │  计数排序   │
│  (建立直觉)      │          │ (分治思想)       │         │ (突破下界)  │
└────────┬────────┘          └────────┬─────────┘         └────────────┘
         │                            │
         ▼                            ▼
    希尔排序                     JDK 的实际选择
  (增量思想过渡)              ┌──────────────────┐
                              │ 基本类型: Dual-Pivot Quicksort │
                              │ 对象类型: TimSort (归并+插入)   │
                              └──────────────────┘
```

## 要点总结

1. **O(n²) 简单排序**：实现简单，适合小规模或教学——重点在于建立对「比较-交换」的直觉
2. **快速排序**：通用场景最快，JDK 对基本类型的默认排序——掌握分治思想是关键
3. **归并排序**：唯一保证 O(n log n) 的比较排序，但需额外空间——链表排序的最佳选择
4. **计数排序**：突破比较排序 O(n log n) 下界，但仅适用于整数且值域不能太大
5. **JDK 的实际选择**：基本类型 → Dual-Pivot Quicksort；对象类型 → TimSort（归并 + 插入混合）

> ### 💡 新人小结：学完排序后你应该带走什么？
>
> 1. **比较排序的下界是 O(n log n)**——这不是某个算法的局限，而是数学定理。想突破只能另辟蹊径（如计数排序）
> 2. **没有「最好」的排序算法**——每种算法都有自己的最佳适用场景，工程选择就是权衡
> 3. **分治思想**从快排和归并中首次登场，后续在树、图、动态规划中会反复出现
> 4. **稳定性**在实际业务中很重要——当你按多个字段排序时（先按姓名、再按年龄），稳定性保证了排序结果的正确性

## 一、完整代码

### ExcelImportParser.java

```java
package com.demo;

import cn.hutool.core.util.StrUtil;
import cn.hutool.poi.excel.ExcelUtil;
import cn.hutool.poi.excel.sax.handler.RowHandler;
import lombok.NonNull;

import java.io.InputStream;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * Excel 导入解析通用工具
 * <pre>
 * 将 Excel 导入解析的样板代码（表头校验、空行跳过、单元格补齐、异常处理）
 * 抽象为 Builder 模式的通用解析器，调用方只需关注行数据到 VO 的映射逻辑。
 *
 * 使用示例：
 * <code>
 * List&lt;MyVO&gt; result = ExcelImportParser.&lt;MyVO&gt;builder()
 *     .inputStream(inputStream)
 *     .expectedTitles(Arrays.asList("姓名", "年龄", "城市"))
 *     .mapper((rowIndex, cellList, titleMap) -&gt; {
 *         MyVO vo = new MyVO();
 *         vo.setName(ExcelImportParser.getCellStr(cellList, titleMap, "姓名"));
 *         vo.setAge(ExcelImportParser.getCellStr(cellList, titleMap, "年龄"));
 *         return vo;
 *     })
 *     .parse();
 * </code>
 * </pre>
 *
 * @param <T> 目标数据类型
 */
public class ExcelImportParser<T> {

    // ==================== 函数式接口 ====================

    /**
     * 行数据映射器：将一行 Excel 数据转换为目标对象
     */
    @FunctionalInterface
    public interface RowMapper<T> {
        /**
         * @param rowIndex      行号（0-based）
         * @param cellList      单元格值列表（已补齐，元素非 null）
         * @param titleIndexMap 列名 → 列索引映射
         * @return 目标对象
         */
        T map(long rowIndex, List<Object> cellList, Map<String, Integer> titleIndexMap);
    }

    // ==================== 字段 ====================

    private InputStream inputStream;
    private List<String> expectedTitles;
    private int sheetIndex = 0;
    private boolean validateHeader = true;
    private long headerRowIndex = 0;
    private long dataStartRow = 1;
    private RowMapper<T> mapper;

    private ExcelImportParser() {
    }

    // ==================== 静态工厂 ====================

    /**
     * 创建 Builder 实例
     */
    public static <T> ExcelImportParser<T> builder() {
        return new ExcelImportParser<>();
    }

    // ==================== Builder 链式方法 ====================

    public ExcelImportParser<T> inputStream(@NonNull InputStream inputStream) {
        this.inputStream = inputStream;
        return this;
    }

    public ExcelImportParser<T> expectedTitles(@NonNull List<String> expectedTitles) {
        this.expectedTitles = new ArrayList<>(expectedTitles);
        return this;
    }

    public ExcelImportParser<T> sheetIndex(int sheetIndex) {
        this.sheetIndex = sheetIndex;
        return this;
    }

    public ExcelImportParser<T> validateHeader(boolean validateHeader) {
        this.validateHeader = validateHeader;
        return this;
    }

    /**
     * 指定表头行号（0-based），默认 0
     * <p>表头行之前的行会被跳过，表头行之后的行根据 dataStartRow 决定是否作为数据行解析。</p>
     */
    public ExcelImportParser<T> headerRowIndex(long headerRowIndex) {
        this.headerRowIndex = headerRowIndex;
        return this;
    }

    public ExcelImportParser<T> dataStartRow(long dataStartRow) {
        this.dataStartRow = dataStartRow;
        return this;
    }

    public ExcelImportParser<T> mapper(@NonNull RowMapper<T> mapper) {
        this.mapper = mapper;
        return this;
    }

    // ==================== 核心解析 ====================

    /**
     * 执行解析
     *
     * @return 解析结果列表
     * @throws BizException 表头校验失败或文件解析异常
     */
    public List<T> parse() {
        if (inputStream == null) {
            throw new IllegalArgumentException("inputStream 不能为空");
        }
        if (expectedTitles == null || expectedTitles.isEmpty()) {
            throw new IllegalArgumentException("expectedTitles 不能为空");
        }
        if (mapper == null) {
            throw new IllegalArgumentException("mapper 不能为空");
        }

        List<T> result = new ArrayList<>();
        Map<String, Integer> titleIndexMap = buildTitleIndexMap(expectedTitles);
        int columnCount = expectedTitles.size();

        try {
            ExcelUtil.readBySax(inputStream, sheetIndex, new RowHandler() {
                @Override
                public void handle(int sheetIndex, long rowIndex, List<Object> cellList) {
                    // 表头行：校验标题
                    if (rowIndex == headerRowIndex && validateHeader) {
                        validateHeaders(cellList);
                    }
                    // 数据行
                    if (rowIndex >= dataStartRow) {
                        if (isRowEmpty(cellList)) {
                            return;
                        }
                        padCellList(cellList, columnCount);
                        T obj = mapper.map(rowIndex, cellList, titleIndexMap);
                        if (obj != null) {
                            result.add(obj);
                        }
                    }
                }
            });
        } catch (BizException e) {
            throw e;
        } catch (Exception e) {
            throw new BizException(
                    SysRetCodeConstants.FAILED.getCode(),
                    "文件解析异常，请确保文件完整且未被加密: " + e.getMessage(),
                    e);
        }

        return result;
    }

    // ==================== 私有方法 ====================

    /**
     * 校验表头行是否与期望标题匹配
     */
    private void validateHeaders(List<Object> actualHeaders) {
        List<String> actual = new ArrayList<>();
        for (Object cell : actualHeaders) {
            actual.add(cell != null ? StrUtil.trim(cell.toString()) : "");
        }
        for (int i = 0; i < expectedTitles.size(); i++) {
            String expected = StrUtil.trim(expectedTitles.get(i));
            String act = i < actual.size() ? actual.get(i) : "";
            if (!StrUtil.equals(expected, act)) {
                throw new BizException(
                        SysRetCodeConstants.FAILED.getCode(),
                        String.format("文件解析异常:标题行不匹配(解析列[%s],excel中对应列为[%s])!", expected, act));
            }
        }
    }

    /**
     * 判断是否为空行（所有单元格为 null 或空白）
     */
    private boolean isRowEmpty(List<Object> cellList) {
        if (cellList == null || cellList.isEmpty()) {
            return true;
        }
        for (Object cell : cellList) {
            if (cell != null && StrUtil.isNotBlank(cell.toString())) {
                return false;
            }
        }
        return true;
    }

    /**
     * 补齐单元格列表：null 替换为空串，长度不足时用空串补齐
     */
    private void padCellList(List<Object> cellList, int expectedSize) {
        int currentSize = cellList.size();
        if (currentSize < expectedSize) {
            for (int i = 0; i < expectedSize - currentSize; i++) {
                cellList.add(StrUtil.EMPTY);
            }
        }
        for (int i = 0; i < cellList.size(); i++) {
            if (cellList.get(i) == null) {
                cellList.set(i, StrUtil.EMPTY);
            }
        }
    }

    /**
     * 构建列名 → 列索引映射
     */
    private Map<String, Integer> buildTitleIndexMap(List<String> titles) {
        Map<String, Integer> map = new HashMap<>();
        for (int i = 0; i < titles.size(); i++) {
            map.put(StrUtil.trim(titles.get(i)), i);
        }
        return map;
    }

    // ==================== 公共静态工具方法 ====================

    /**
     * 按列名获取单元格的字符串值（trim 后），不存在则返回空串
     *
     * @param cellList      单元格值列表（已由 parse 补齐，元素非 null）
     * @param titleIndexMap 列名 → 列索引映射
     * @param columnName    列名
     * @return 单元格字符串值（trim 后），列不存在或值为空时返回 ""
     */
    public static String getCellStr(List<Object> cellList, Map<String, Integer> titleIndexMap, String columnName) {
        Integer index = titleIndexMap.get(columnName);
        if (index == null || index >= cellList.size()) {
            return "";
        }
        Object val = cellList.get(index);
        return val != null ? val.toString().trim() : "";
    }
}
```

## 二、核心设计思想

### 1. Builder 模式 + 链式配置

将解析所需的全部参数（inputStream、expectedTitles、sheetIndex、headerRowIndex、validateHeader、dataStartRow、mapper）统一收归到 Builder 链式调用中，调用方按需配置，未配置的参数使用合理默认值。

**优势**：

- 参数多但不混乱——每个参数有明确的 setter 名称
- 默认值合理——大多数场景只需 3 个必填参数
- 可读性强——`.inputStream().expectedTitles().mapper().parse()` 链式调用，意图一目了然

### 2. Hutool SAX 模式（低内存大文件解析）

底层使用 `ExcelUtil.readBySax()`，而非 DOM 模式（`new XSSFWorkbook(inputStream)`）。SAX 模式逐行回调，不会将整个文件加载到内存。

**优势**：

- 内存占用恒定——不随文件大小增长
- 适合大文件——百万行级别也能稳定解析
- 流式消费——InputStream 只读一次，无需缓存

### 3. 函数式 RowMapper（业务逻辑与基础设施分离）

通过 `@FunctionalInterface RowMapper<T>` 将"一行数据如何映射为对象"的逻辑交给调用方，工具只负责"如何读取一行"的基础设施。

**优势**：

- 调用方只需写 mapper lambda，不接触 SAX 细节
- 工具可独立演进（优化读取、增强校验），不影响业务映射逻辑
- lambda 可复用——同一 mapper 可用于不同数据源

### 4. 内置样板抽象（表头校验 + 空行跳过 + 单元格补齐 + 异常包装）

将 4 类重复样板代码全部内置：

| 样板 | 内置行为 |
|------|----------|
| 表头校验 | `validateHeaders()` 逐列 trim 比较 |
| 空行跳过 | `isRowEmpty()` 判断后跳过 |
| 单元格补齐 | `padCellList()` null 替换 + 长度补齐 |
| 异常包装 | BizException 透传，其他包装为 BizException |

### 5. titleIndexMap 按列名取值

`buildTitleIndexMap()` 构建列名→列索引映射，传给 mapper。调用方通过 `getCellStr(cellList, titleMap, "列名")` 按列名取值，而非硬编码索引。

**优势**：

- 列顺序变化时 mapper 代码无需修改
- 可读性强——`getCellStr(cellList, titleMap, "订单单号")` 比 `cellList.get(0)` 语义清晰

## 三、解决的问题

### 问题 1：表头校验样板重复

每个导入接口都要手写 `if (rowIndex == 0) { 逐列 trim 比较 }` 逻辑，15 列就写 15 行比较代码。

**解决**：`validateHeaders()` 内置，调用方只需传入 `expectedTitles`。

### 问题 2：空行判断逻辑散落

每个导入接口都要手写 `cellList.stream().anyMatch(x -> !StringUtils.isEmpty(x))` 判断空行。

**解决**：`isRowEmpty()` 内置，空行自动跳过，不进入 mapper。

### 问题 3：单元格补齐方法重复

每个导入接口都要手写 `fillListWithEmptyStr()` 私有方法（13 行），处理 null 替换和长度补齐。

**解决**：`padCellList()` 内置，mapper 拿到的 cellList 已补齐且无 null。

### 问题 4：异常处理框架重复

每个导入接口都要写 `catch (BizException e) { ... } catch (Exception e) { ... }` 两段式异常处理。

**解决**：`parse()` 内部统一处理——BizException 透传，其他异常包装为 BizException。调用方的 catch 结构简化。

### 问题 5：取值方式硬编码索引

原始代码用 `cellList.get(0)`、`cellList.get(1)` 硬编码索引，列顺序变化时所有索引都要改。

**解决**：`getCellStr(cellList, titleMap, "列名")` 按列名取值，不受列顺序影响。

## 四、架构设计

```
ExcelImportParser<T>
│
├── 函数式接口层
│   └── RowMapper<T>              行数据映射器（@FunctionalInterface）
│
├── Builder 配置层
│   ├── inputStream()             文件输入流（必填）
│   ├── expectedTitles()          期望标题列表（必填，防御性拷贝）
│   ├── sheetIndex()              Sheet 索引（默认 0）
│   ├── headerRowIndex()          表头行号（默认 0）
│   ├── validateHeader()          是否校验表头（默认 true）
│   ├── dataStartRow()            数据起始行（默认 1）
│   └── mapper()                  行映射器（必填）
│
├── 核心解析层
│   └── parse()                   参数校验 → SAX 逐行回调 → 结果收集
│       ├── validateHeaders()     表头校验（逐列 trim 比较）
│       ├── isRowEmpty()          空行判断
│       ├── padCellList()         单元格补齐
│       └── buildTitleIndexMap()  列名→索引映射
│
└── 工具方法层
    └── getCellStr()              按列名获取单元格字符串值（静态公共）
```

**依赖关系**：

- 底层依赖 Hutool `ExcelUtil.readBySax()` 进行 SAX 解析
- 异常依赖 `BizException` + `SysRetCodeConstants` 进行统一包装
- 字符串工具依赖 Hutool `StrUtil`（trim、isNotBlank、EMPTY）

## 五、存在的问题

### A 类：Bug 级问题

#### A1. titleIndexMap 使用 HashMap（无序）

`buildTitleIndexMap()` 使用 `HashMap`，迭代顺序不确定。虽然 `getCellStr` 按列名查找不受影响，但如果调用方遍历 titleIndexMap（如调试打印），顺序与 expectedTitles 不一致，增加排查成本。

**建议**：改用 `LinkedHashMap`，保持插入顺序。

#### A2. validateHeaders 边界保护不完整

`validateHeaders()` 中 `actual` 列表由 `actualHeaders` 构建，长度可能小于 `expectedTitles`。虽然 `i < actual.size()` 做了保护，但如果 `actualHeaders` 本身为 null 或空，`actual` 也为空，所有列都会与空串比较——错误信息可能不够明确（显示"解析列[姓名],excel中对应列为[]"）。

**建议**：在 `validateHeaders` 开头增加 `actualHeaders` 为 null/空的快速失败。

#### A3. headerRowIndex 与 dataStartRow 语义耦合

`headerRowIndex` 默认为 0，`dataStartRow` 默认为 1。如果调用方设置了 `headerRowIndex(2)` 但忘记设置 `dataStartRow(3)`，表头行本身会被当作数据行解析（因为 `dataStartRow` 仍为 1，而 `rowIndex == 2 >= 1`）。

**建议**：在 `parse()` 中增加 `dataStartRow > headerRowIndex` 的校验或自动推导。

### B 类：设计缺陷

#### B1. InputStream 无关闭机制

`parse()` 消费了 InputStream 但从不关闭它。调用方需要自行在 finally 中关闭。如果调用方忘记关闭，可能导致资源泄漏。

**建议**：提供 `parseAndClose()` 方法，或在文档中明确标注调用方需负责关闭。

#### B2. 不支持多 Sheet 批量解析

当前只能解析单个 Sheet（由 `sheetIndex` 指定）。如果调用方需要解析多个 Sheet，需要创建多个 builder 实例，每个指定不同的 `sheetIndex`。

**建议**：提供 `parseAllSheets()` 或 `parseSheets(List<Integer> sheetIndices)` 方法。

#### B3. 无解析进度回调

对于大文件解析（如百万行），调用方无法获知解析进度。SAX 模式本身是逐行回调，增加进度回调成本很低。

**建议**：增加 `onProgress(long rowIndex)` 回调接口。

#### B4. getCellStr 只返回 String

`getCellStr` 只返回 String 类型。对于数值型字段（如"销售数量"），调用方需要手动 `Integer.parseInt()` 或 `Double.parseDouble()`。SAX 模式下数值单元格可能是 `Double` 类型，`toString()` 后会产生 `"25.0"` 格式。

**建议**：增加 `getCellInt()`、`getCellLong()`、`getCellBigDecimal()` 等类型安全的工具方法。

### C 类：代码质量

#### C1. 魔法数字

`sheetIndex = 0`、`headerRowIndex = 0`、`dataStartRow = 1` 等默认值直接硬编码在字段声明中。虽然语义清晰，但如果后续需要调整默认策略（如 dataStartRow 改为跟随 headerRowIndex + 1），需要修改多处。

**建议**：提取为命名常量 `DEFAULT_SHEET_INDEX`、`DEFAULT_HEADER_ROW_INDEX`、`DEFAULT_DATA_START_ROW`。

#### C2. parse() 方法较长

`parse()` 方法包含参数校验、titleIndexMap 构建、SAX 回调定义、异常处理，约 40 行。虽然逻辑清晰，但可以进一步拆分。

**建议**：将 SAX 回调逻辑提取为 `createRowHandler()` 私有方法。

#### C3. 无数据校验框架

当前只有表头格式校验，没有数据业务校验（如必填字段为空、数值超出范围、日期格式错误等）。调用方需要在 mapper 中手动校验并抛出异常，或者在 `parse()` 后对结果列表做二次校验。

**建议**：提供 `RowValidator` 接口，在 mapper 之前执行校验，校验失败可收集错误行而非立即中断。

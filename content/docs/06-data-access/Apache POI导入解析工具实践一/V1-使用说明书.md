# ExcelImportParser 使用说明书

## 一、工具定位

`ExcelImportParser` 是一个基于 Hutool SAX 模式的 Excel 导入解析通用工具，采用 Builder + 函数式 RowMapper 设计。

**核心能力：**

- **表头自动校验** — 在 `headerRowIndex`（默认第 0 行）处与 `expectedTitles` 逐列 trim 比较，不匹配抛 `BizException`
- **空行自动跳过** — 所有单元格为 null/空白 的行不进入 mapper
- **单元格自动补齐** — cellList 长度不足时用空串补齐，null 元素替换为空串
- **异常统一包装** — `BizException` 透传，其他异常包装为 `BizException`
- **titleIndexMap** — 传给 mapper 的列名→列索引映射，支持按列名取值，不受列顺序影响
- **可配置** — sheetIndex、headerRowIndex、validateHeader、dataStartRow 等灵活配置

**与原始手写代码的对比：**

| 原始代码（79 行） | ExcelImportParser（约 15 行） |
|---|---|
| 手动定义 RowHandler、判断 rowIndex | 只需提供 mapper lambda |
| 手动 trim 比较表头 | 内置表头校验 |
| 手动 fillListWithEmptyStr 补齐 | 内置单元格补齐 |
| 手动判断空行 | 内置空行跳过 |
| 手动 try-catch 分别处理异常 | 内置异常包装 |

## 二、场景速查（按使用场景组织）

### 场景 1：最基本的导入解析

```java
List<String> titles = Arrays.asList("姓名", "年龄", "城市");

List<MyVO> result = ExcelImportParser.<MyVO>builder()
    .inputStream(multipartFile.getInputStream())
    .expectedTitles(titles)
    .mapper((rowIndex, cellList, titleMap) -> {
        MyVO vo = new MyVO();
        vo.setName(ExcelImportParser.getCellStr(cellList, titleMap, "姓名"));
        vo.setAge(ExcelImportParser.getCellStr(cellList, titleMap, "年龄"));
        vo.setCity(ExcelImportParser.getCellStr(cellList, titleMap, "城市"));
        return vo;
    })
    .parse();
```

> 默认行为：解析第 0 个 Sheet、校验表头、从第 1 行开始解析数据。

### 场景 2：在 Controller 中使用（含异常处理）

```java
@PostMapping("/import")
public Result importExcel(@RequestParam("file") MultipartFile file) {
    Result rp = new Result();
    List<String> titles = Arrays.asList("订单单号", "订单类型", "备件编码", "备件名称");

    try {
        List<OrderImportVO> list = ExcelImportParser.<OrderImportVO>builder()
            .inputStream(file.getInputStream())
            .expectedTitles(titles)
            .mapper((rowIndex, cellList, titleMap) -> {
                OrderImportVO vo = new OrderImportVO();
                vo.setBillNo(ExcelImportParser.getCellStr(cellList, titleMap, "订单单号"));
                vo.setOrderType(ExcelImportParser.getCellStr(cellList, titleMap, "订单类型"));
                vo.setGoodsCode(ExcelImportParser.getCellStr(cellList, titleMap, "备件编码"));
                vo.setGoodsName(ExcelImportParser.getCellStr(cellList, titleMap, "备件名称"));
                return vo;
            })
            .parse();

        // 业务处理...
        return rp.setSuccess(list);

    } catch (BizException e) {
        return rp.setErrorMsg(e.getErrorCode(), e.getMessage());
    } catch (Exception e) {
        return rp.setErrorMsg(SysRetCodeConstants.FAILED.getCode(),
            "文件解析异常，请确保文件完整且未被加密");
    }
}
```

> `parse()` 内部的 `BizException`（表头不匹配等）会透传，其他异常会被包装为 `BizException`。

### 场景 3：表头不在第 0 行（前面有标题行）

某些 Excel 前面有报表标题，表头在更下面的行：

```
| 员工信息报表                    |    ← 第 0 行（标题行，应跳过）
| 姓名 | 年龄 | 城市 |            ← 第 1 行（表头，由 headerRowIndex 指定）
| 张三 | 25   | 北京 |            ← 第 2 行（数据开始，由 dataStartRow 指定）
```

```java
ExcelImportParser.<MyVO>builder()
    .inputStream(inputStream)
    .expectedTitles(Arrays.asList("姓名", "年龄", "城市"))
    .headerRowIndex(1)   // 表头在第 1 行
    .dataStartRow(2)     // 数据从第 2 行开始
    .mapper((rowIndex, cellList, titleMap) -> {
        // ...
    })
    .parse();
```

> `headerRowIndex` 默认值为 `0`。设为其他值时，该行会被用于表头校验，之前的行全部跳过。

### 场景 4：表头与数据之间有说明行

某些 Excel 模板在表头和数据之间有一行说明文字：

```
| 姓名 | 年龄 | 城市 |    ← 第 0 行（表头）
| 请填写 | 请勿留空 |       |    ← 第 1 行（说明行，应跳过）
| 张三 | 25   | 北京 |    ← 第 2 行（实际数据开始）
```

```java
ExcelImportParser.<MyVO>builder()
    .inputStream(inputStream)
    .expectedTitles(Arrays.asList("姓名", "年龄", "城市"))
    .dataStartRow(2)   // 从第 2 行开始解析，跳过第 1 行说明行
    .mapper((rowIndex, cellList, titleMap) -> {
        // ...
    })
    .parse();
```

> `dataStartRow` 默认值为 `1`（即表头后紧接着就是数据）。设为 `2` 则跳过一行说明行。

### 场景 5：关闭表头校验

当 Excel 文件的表头不可靠或与期望不一致但仍需解析时：

```java
ExcelImportParser.<MyVO>builder()
    .inputStream(inputStream)
    .expectedTitles(Arrays.asList("姓名", "年龄"))
    .validateHeader(false)   // 关闭表头校验
    .mapper((rowIndex, cellList, titleMap) -> {
        // 此时 titleIndexMap 仍基于 expectedTitles 构建
        // 但不会校验 Excel 实际表头是否匹配
        MyVO vo = new MyVO();
        vo.setName(cellList.get(0).toString().trim());  // 可用索引直接取值
        vo.setAge(cellList.get(1).toString().trim());
        return vo;
    })
    .parse();
```

> **注意**：关闭校验后，`titleIndexMap` 仍基于 `expectedTitles` 构建。如果 Excel 实际列顺序与 `expectedTitles` 不同，`getCellStr` 按列名取值会取到错误的数据。此时建议用 `cellList.get(index)` 按索引取值。

### 场景 7：mapper 中使用 rowIndex 做条件判断

`RowMapper` 的第一个参数 `rowIndex` 是当前行号（0-based），可用于条件逻辑：

```java
.mapper((rowIndex, cellList, titleMap) -> {
    MyVO vo = new MyVO();
    vo.setName(ExcelImportParser.getCellStr(cellList, titleMap, "姓名"));
    vo.setAge(ExcelImportParser.getCellStr(cellList, titleMap, "年龄"));

    // 根据行号设置不同默认值
    if (rowIndex == 1) {
        vo.setRowNumber("first");
    }

    return vo;
})
```

### 场景 8：mapper 返回 null 跳过该行（数据过滤）

mapper 返回 `null` 时，该行不会被加入结果列表。可用于数据过滤：

```java
.mapper((rowIndex, cellList, titleMap) -> {
    String name = ExcelImportParser.getCellStr(cellList, titleMap, "姓名");
    if (StrUtil.isEmpty(name)) {
        return null;   // 姓名为空的行不加入结果
    }
    MyVO vo = new MyVO();
    vo.setName(name);
    return vo;
})
```

> 注意：这与"空行跳过"不同。空行跳过是整行所有单元格都为空；这里是 mapper 内部的业务逻辑过滤。

---

### 场景 9：处理数值类型单元格

SAX 模式下，数值单元格（如 `25`）在 `cellList` 中可能是 `Double` 类型。`getCellStr` 会自动调用 `toString().trim()`，对于 `Double` 值会产生 `"25.0"` 这样的字符串。

如果需要精确处理数值：

```java
.mapper((rowIndex, cellList, titleMap) -> {
    MyVO vo = new MyVO();

    // 方式 1：使用 getCellStr（适合字符串字段）
    vo.setName(ExcelImportParser.getCellStr(cellList, titleMap, "姓名"));

    // 方式 2：直接取原始值并转换（适合数值字段）
    Integer ageIndex = titleMap.get("年龄");
    Object ageVal = cellList.get(ageIndex);
    if (ageVal instanceof Double) {
        vo.setAge(((Double) ageVal).intValue());
    } else if (ageVal instanceof String) {
        vo.setAge(Integer.parseInt(((String) ageVal).trim()));
    }

    return vo;
})
```

---

### 场景 10：按索引取值（替代 getCellStr）

如果确定 Excel 列顺序固定，可以直接按索引取值，代码更简洁：

```java
.mapper((rowIndex, cellList, titleMap) -> {
    MyVO vo = new MyVO();
    vo.setName(cellList.get(0).toString().trim());   // 第 0 列：姓名
    vo.setAge(cellList.get(1).toString().trim());     // 第 1 列：年龄
    vo.setCity(cellList.get(2).toString().trim());    // 第 2 列：城市
    return vo;
})
```

> **推荐**：使用 `getCellStr(cellList, titleMap, "列名")` 按列名取值。这样即使 Excel 列顺序发生变化，代码也无需修改。

## 三、API 速查

### Builder 配置方法

| 方法 | 默认值 | 说明 |
|------|--------|------|
| `.inputStream(InputStream)` | **必填** | Excel 文件输入流 |
| `.expectedTitles(List<String>)` | **必填** | 期望的列名列表，用于表头校验和构建 titleIndexMap |
| `.mapper(RowMapper<T>)` | **必填** | 行数据映射函数 |
| `.sheetIndex(int)` | `0` | 要解析的 Sheet 索引（0-based） |
| `.headerRowIndex(long)` | `0` | 表头行号（0-based），该行用于表头校验 |
| `.validateHeader(boolean)` | `true` | 是否校验表头行与 expectedTitles 匹配 |
| `.dataStartRow(long)` | `1` | 数据起始行号（0-based），之前的行会被跳过 |

### RowMapper 函数式接口

```java
@FunctionalInterface
public interface RowMapper<T> {
    T map(long rowIndex, List<Object> cellList, Map<String, Integer> titleIndexMap);
}
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `rowIndex` | `long` | 当前行号（0-based） |
| `cellList` | `List<Object>` | 单元格值列表，已补齐（长度 >= expectedTitles.size()），元素非 null |
| `titleIndexMap` | `Map<String, Integer>` | 列名 → 列索引映射 |

### 静态工具方法

```java
// 按列名获取单元格的字符串值（trim 后），列不存在返回 ""
String value = ExcelImportParser.getCellStr(cellList, titleIndexMap, "列名");
```

## 四、异常速查

| 异常类型 | 触发条件 | 解决方案 |
|----------|----------|----------|
| `IllegalArgumentException` | `inputStream` 为 null | 确保传入有效的 InputStream |
| `IllegalArgumentException` | `expectedTitles` 为 null 或空 | 至少提供一列期望标题 |
| `IllegalArgumentException` | `mapper` 为 null | 必须提供 RowMapper |
| `BizException` | 表头校验失败（`validateHeader=true` 时） | 检查 Excel 文件表头是否与 expectedTitles 一致 |
| `BizException` | 文件解析异常（IO 异常、格式错误等） | 确保文件完整且未被加密 |

> 表头校验失败的错误信息格式：`文件解析异常:标题行不匹配(解析列[期望列名],excel中对应列为[实际列名])!`

## 五、内置行为详解

### 表头校验

- 发生在 `rowIndex == headerRowIndex` 时（`headerRowIndex` 默认为 0）
- 逐列 trim 后比较，忽略前后空格
- 如果 Excel 实际列数少于 expectedTitles，缺失列视为空串，与期望不匹配
- 如果 Excel 实际列数多于 expectedTitles，多余列被忽略（不报错）
- 校验失败抛出 `BizException`，不会继续解析后续行

### 空行跳过

- 判定标准：cellList 中所有元素均为 null 或空白字符串
- 空行不进入 mapper，不加入结果列表
- 空行判断发生在单元格补齐之前

### 单元格补齐

- 发生在空行判断之后
- null 元素替换为 `""`（空串）
- cellList 长度不足 expectedTitles.size() 时，末尾补 `""`
- 补齐后 cellList 长度 >= expectedTitles.size()

### 异常处理

- `BizException`（包括表头校验失败）直接透传
- 其他所有异常（IOException、RuntimeException 等）被包装为 `BizException`，错误码为 `SysRetCodeConstants.FAILED`，消息为 `"文件解析异常，请确保文件完整且未被加密: {原始消息}"`

---

## 六、注意事项

1. **调用顺序**：`builder()` → 配置方法 → `parse()`，`parse()` 执行后 InputStream 被消费，不可重复使用。
2. **cellList 元素类型**：SAX 模式下，字符串单元格为 `String`，数值单元格可能为 `Double`，日期单元格可能为 `String`（格式化后）或 `Date`。使用 `getCellStr` 会调用 `toString().trim()`，对于 `Double` 值可能产生 `"25.0"` 格式。如需精确数值处理，请直接操作 `cellList` 中的原始值。
3. **titleIndexMap 基于 expectedTitles**：不是基于 Excel 实际表头。如果关闭了表头校验且 Excel 列顺序与 expectedTitles 不同，`getCellStr` 按列名取值会取到错误数据。
4. **mapper 返回 null 安全**：mapper 返回 null 时该行被跳过，不会加入结果列表，不会导致 NPE。
5. **线程安全**：`ExcelImportParser` 实例不是线程安全的，每次解析应创建新的 builder 实例。
6. **大文件友好**：底层使用 Hutool SAX 模式（`ExcelUtil.readBySax`），不会将整个文件加载到内存，适合大文件解析。
7. **仅支持 xls/xlsx**：底层依赖 Hutool POI，支持 `.xls`（HSSF）和 `.xlsx`（XSSF）格式。

## 七、真实业务场景对比：CurCcaPo 导入

以下以一份真实的备件订单导入代码为例，完整展示原始手写方式与使用 `ExcelImportParser` 后的对比。

### 原始代码（79 行）

```java
List<CurCcaPoImportVO> importVOList = new ArrayList<>();
List<String> excelTitlesCommon = ListUtil.of(
        "订单单号",
        "订单类型",
        "备件编码",
        "备件名称",
        "备件件号",
        "销售数量",
        "订单明细备注",
        "型号",
        "接收单位",
        "接收地址",
        "接收人",
        "联系电话",
        "备注",
        "ERP订单",
        "状态");
try {
    ExcelUtil.readBySax(multipartFile.getInputStream(), 0, new RowHandler() {
        @Override
        public void handle(int sheetIndex, long rowIndex, List<Object> cellList) {
            // 解析第1行的文档标题
            if (rowIndex == 0) {
                List<String> excelTitlesInExcel = cellList.stream()
                    .filter(Objects::nonNull).map(Object::toString).collect(Collectors.toList());
                for (int i = 0; i < excelTitlesCommon.size(); i++) {
                    String trimmedX = StrUtil.trim(excelTitlesCommon.get(i));
                    String trimmedY = StrUtil.trim(excelTitlesInExcel.get(i));
                    if (!StrUtil.equals(trimmedX, trimmedY)) {
                        throw new BizException(SysRetCodeConstants.FAILED.getCode(),
                            String.format("文件解析异常:标题行不匹配(解析列[%s],excel中对应列为[%s])!",
                                trimmedX, trimmedY));
                    }
                }
            }
            // 从第2行开始解析数据
            if (rowIndex >= 1) {
                if (cellList.stream().anyMatch(x -> !StringUtils.isEmpty(x))) {
                    fillListWithEmptyStr(cellList, excelTitlesCommon.size());
                    CurCcaPoImportVO importVO = new CurCcaPoImportVO();
                    importVO.setBillNo(cellList.get(0).toString().trim());
                    importVO.setCcaPoType(cellList.get(1).toString().trim());
                    importVO.setIsBack(false);
                    importVO.setCcaGoodsCode(cellList.get(2).toString().trim());
                    importVO.setCcaGoodsName(cellList.get(3).toString().trim());
                    importVO.setCcaGoodsNo(cellList.get(4).toString().trim());
                    importVO.setPoQty(cellList.get(5).toString().trim());
                    importVO.setPoMemo(cellList.get(6).toString().trim());
                    importVO.setCcaGoodsSpecdesc(cellList.get(7).toString().trim());
                    importVO.setReceiveCustname(cellList.get(8).toString().trim());
                    importVO.setReceiveAddr(cellList.get(9).toString().trim());
                    importVO.setReceiveName(cellList.get(10).toString().trim());
                    importVO.setReceiveTel(cellList.get(11).toString().trim());
                    importVO.setMemo(cellList.get(12).toString().trim());
                    importVO.setErpOrder_(cellList.get(13).toString().trim());
                    importVO.setStatus_(cellList.get(14).toString().trim());
                    importVOList.add(importVO);
                }
            }
        }

        private void fillListWithEmptyStr(final List<Object> rowCells, final int count) {
            final int tmpSize = rowCells.size();
            if (tmpSize < count) {
                for (int i = 0; i < count - tmpSize; i++) {
                    rowCells.add(StrUtil.EMPTY);
                }
            }
            for (int i = 0; i < rowCells.size(); i++) {
                if (rowCells.get(i) == null) {
                    rowCells.set(i, StrUtil.EMPTY);
                }
            }
        }
    });
} catch (BizException e) {
    LOGGER.error(">>>>>>>>|CurCcaPo importExcel|BizException|文件解析异常:{}|<<<<<<<<",
        e.getMessage(), e);
    return rp.setErrorMsg(e.getErrorCode(), e.getMessage());
} catch (Exception e) {
    LOGGER.error(">>>>>>>>|CurCcaPo importExcel|Exception|文件解析异常，请确保文件完整且未被加密:{}|<<<<<<<<",
        e.getMessage(), e);
    return rp.setErrorMsg(SysRetCodeConstants.FAILED.getCode(),
        "文件解析异常，请确保文件完整且未被加密");
}
```

```java
    LOGGER.error(">>>>>>>>|CurCcaPo importExcel|Exception|文件解析异常，请确保文件完整且未被加密:{}|<<<<<<<<",
        e.getMessage(), e);
    return rp.setErrorMsg(SysRetCodeConstants.FAILED.getCode(),
        "文件解析异常，请确保文件完整且未被加密");
}
```

## 八、性能优化与架构设计分析

### 1. 性能角度：重复传参的实际开销

当前 `getCellStr(cellList, titleMap, "列名")` 每次调用的执行路径：

```java
public static String getCellStr(List<Object> cellList, Map<String, Integer> titleIndexMap, String columnName) {
    Integer index = titleIndexMap.get(columnName);   // ① HashMap.get：hashCode + equals
    if (index == null || index >= cellList.size())    // ② 边界检查
        return "";
    Object val = cellList.get(index);                 // ③ ArrayList.get：O(1)
    return val != null ? val.toString().trim() : "";  // ④ toString + trim
}
```

以 15 列 x 1000 行为例：

| 操作 | 单次成本 | 1000 行总次数 | 实际影响 |
|------|---------|-------------|----------|
| ① HashMap.get(String) | hashCode 计算 + equals | 15,000 次 | **主要开销**，但 String.hashCode 被 JVM 缓存 |
| ② 边界检查 | 两次比较 | 15,000 次 | 可忽略 |
| ③ ArrayList.get(int) | 数组直接寻址 | 15,000 次 | 可忽略 |
| ④ toString().trim() | 新建 String 对象 | 15,000 次 | 主要 GC 压力，但与传参方式无关 |

**结论**：`String.hashCode()` 在 Java 中只计算一次并缓存，15 次 HashMap lookup/行相对于 SAX 解析 I/O 开销差 3 个数量级。**性能不是真实瓶颈**。

### 2. 架构角度：真正值得改进的问题

| 问题 | 说明 |
|------|------|
| 参数冗余 | 每次调用都要写 `cellList, titleMap` 两个参数，15 列就写 15 次 |
| 类型单一 | 只返回 String，数值/日期需调用方手动转换 |
| 逻辑冗余 | 列名→索引映射在整个解析过程中不变，但每行重复查找 |
| 易错性 | 漏传或错传参数时编译器不会报错（参数类型相同） |

### 3. 改进方案：引入 RowAccessor

将 `cellList + titleIndexMap` 封装为行级访问器，mapper 只需操作一个对象：

```java
// V1 写法：每行 3 个参数
ExcelImportParser.getCellStr(cellList, titleMap, "订单单号");

// V2 写法：1 个参数，支持多类型
row.getString("订单单号");
row.getInteger("销售数量");
row.getDecimal("金额");
```

**V2 改进对比：**

| 维度 | V1（getCellStr） | V2（RowAccessor） |
|------|------------------|--------------------|
| 调用方参数 | 3 个（cellList, titleMap, columnName） | 1 个（columnName） |
| 返回类型 | 只有 String | String / Integer / Long / BigDecimal / Object |
| RowMapper 签名 | `map(rowIndex, cellList, titleMap)` | `map(rowIndex, row)` |
| 列顺序抗变 | 按列名，抗变 | 按列名，抗变 |
| 代码可读性 | `getCellStr(cellList, titleMap, "列名")` | `row.getString("列名")` |

> 详细 V2 实现请参考后续 V2 版本文档。

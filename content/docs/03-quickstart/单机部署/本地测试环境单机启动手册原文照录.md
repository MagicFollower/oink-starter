> | 原文说法 | 4.9.8 实测结论 | 判据 |
> |---|---|---|
> | 「Broker Slave（如配置）11011，从节点同步/拉取」 | 本机无 11011 监听。主从复制走主节点的 `haListenPort`（实测 10912）；Slave 对客户端仍用它自己的 `listenPort` | `netstat` 端口实测 + `getBrokerConfig` 回显 `haListenPort=10912` |
> | 「Broker VIP 10909，用途＝高可用/VIP 通道」 | 10909 是 VIP 通道（客户端 `vipChannelEnabled` 默认 true），高可用同步是另一个端口 10912，两件事不能并成一格 | 端口实测 + `docs/06-parameterConfiguration/01local.md` |
> | 「方式 A：`mqadmin startConsoleWeb`，部分 4.x 发行包提供」 | 该命令在 4.9.8 不存在，Web 界面只能起独立的 `rocketmq-dashboard` jar | `jar tf lib/*.jar` 全量扫描，`rocketmq-tools-4.9.8.jar` 的 59 个命令类里无 `StartConsoleWeb` |

以下是一份 **RocketMQ 4.9.8 在 Windows 与 Linux 下的完整操作手册**，覆盖从环境准备、服务启动、状态检测、功能验证到停止的全流程。

---

## 0. 前置准备

### 环境要求
- **JDK**：64-bit JDK 1.8+，`JAVA_HOME` 已正确配置。
- **RocketMQ 4.9.8**：已解压到任意目录（下文以 `%ROCKETMQ_HOME%`（Windows）或 `$ROCKETMQ_HOME`（Linux）代指安装根目录）。

### 关键端口速查
| 组件                   | 默认端口  | 用途            |
| ---------------------- | --------- | --------------- |
| NameServer             | **9876**  | 路由注册与发现  |
| Broker                 | **10911** | 消息收发主端口  |
| Broker VIP             | **10909** | 高可用/VIP 通道 |
| Broker Slave（如配置） | **11011** | 从节点同步/拉取 |

> 如果启用了防火墙，务必放行上述端口，否则 Broker 无法正常注册到 NameServer，客户端也无法通信。

## 1. 启动 NameServer（必须最先启动）

Broker 启动后会主动向 NameServer 注册自己，因此 **NameServer 必须先于 Broker 就绪**。

### 🐧 Linux

```bash
cd $ROCKETMQ_HOME

# 后台启动
nohup sh bin/mqnamesrv >/dev/null 2>&1 &

# 或者将日志显式重定向，便于排查
nohup sh bin/mqnamesrv > namesrv_startup.log 2>&1 &
```

### 🪟 Windows

在 **cmd** 中进入 `bin` 目录：

```cmd
cd /d %ROCKETMQ_HOME%\bin
start mqnamesrv.cmd
```

`start` 会打开一个新的命令行窗口来运行 NameServer，**该窗口不能关闭**，否则 NameServer 会随窗口终止而退出。

---

## 2. 启动 Broker

### 2.1 准备 Broker 配置文件

在 `conf` 目录下准备 `broker.conf`（4.9.8 可用以下最小配置）：

```properties
brokerClusterName=DefaultCluster
brokerName=broker-a
brokerId=0
namesrvAddr=127.0.0.1:9876
listenPort=10911
brokerRole=ASYNC_MASTER
flushDiskType=ASYNC_FLUSH
storePathRootDir=/data/rocketmq/store/broker-a
autoCreateTopicEnable=true
autoCreateSubscriptionGroup=true
```

> Windows 下请将 `storePathRootDir` 改为 Windows 风格路径，例如 `D:\\rocketmq\\store\\broker-a`。

### 2.2 启动命令

#### 🐧 Linux

```bash
cd $ROCKETMQ_HOME

nohup sh bin/mqbroker -c conf/broker.conf -n 127.0.0.1:9876 > broker_startup.log 2>&1 &
```

- `-c`：指定 Broker 配置文件。
- `-n`：显式指定 NameServer 地址，即使配置文件中已写也建议保留，形成双重保障。

#### 🪟 Windows

```cmd
cd /d %ROCKETMQ_HOME%\bin
start mqbroker.cmd -c ../conf/broker.conf -n 127.0.0.1:9876
```

同样会弹出新的 cmd 窗口，**窗口不能关闭**。

## 3. 状态检测（四层验证，逐层深入）

只看进程是否存在远远不够，建议按以下四层依次验证。

### 第一层：Java 进程

#### 🐧 Linux

```bash
jps -l | grep -E "NamesrvStartup|BrokerStartup"
```

预期看到两个进程：
```
xxxx NamesrvStartup
yyyy BrokerStartup
```


#### 🪟 Windows

```cmd
jps -l
```
或使用任务管理器查看是否存在 `NamesrvStartup` / `BrokerStartup` 对应的 Java 进程。

> `jps` 来源于 JDK，如果提示命令不存在，检查 `JAVA_HOME\bin` 是否在 `PATH` 中。

---

### 第二层：监听端口

#### 🐧 Linux

```bash
# NameServer 9876
ss -tlnp | grep 9876
# 或
netstat -tlnp | grep 9876

# Broker 10911
ss -tlnp | grep 10911
```
两个端口都应处于 `LISTEN` 状态。

#### 🪟 Windows

```cmd
netstat -ano | findstr :9876
netstat -ano | findstr :10911
```

---

### 第三层：启动日志

RocketMQ 默认日志目录为 **`${user.home}/logs/rocketmqlogs/`**（Linux 下即 `~/logs/rocketmqlogs/`，Windows 下为 `C:\Users\<用户名>\logs\rocketmqlogs\`）。

#### 🐧 Linux

```bash
# NameServer
tail -n 50 ~/logs/rocketmqlogs/namesrv.log
# 关键成功标志：包含 "The Name Server boot success"

# Broker
tail -n 50 ~/logs/rocketmqlogs/broker.log
# 关键成功标志：包含 "The broker[broker-a, ...] boot success"
```

#### 🪟 Windows

在资源管理器地址栏或 cmd 中查看：
```cmd
type %USERPROFILE%\logs\rocketmqlogs\broker.log
type %USERPROFILE%\logs\rocketmqlogs\namesrv.log
```
重点查找 `boot success` 关键字。

---

### 第四层：`mqadmin` 集群检测（最终确认）

`mqadmin` 位于 `bin` 目录下，Linux 下为 `sh bin/mqadmin ...`，Windows 下为 `mqadmin.cmd ...`。几乎所有命令都需要 `-n` 指定 NameServer 地址。

#### 查看集群列表（最核心的检测命令）

```bash
# Linux
sh bin/mqadmin clusterList -n 127.0.0.1:9876

# Windows
mqadmin.cmd clusterList -n 127.0.0.1:9876
```

**正常输出**会列出 `DefaultCluster`、Broker 名称、BrokerId、地址以及 TPS 等信息。如果这里看不到你的 Broker，说明 Broker **没有成功注册**，进程“活着”但服务未就绪。

#### 查看 Topic 列表

```bash
sh bin/mqadmin topicList -n 127.0.0.1:9876
```
能列出 `RMQ_SYS_TRANS_HALF_TOPIC`、`SELF_TEST_TOPIC` 等系统 Topic，说明 NameServer 路由信息正常。

---

### 可选：设置 `NAMESRV_ADDR` 环境变量（减少重复输入）

如果你不想每次都带 `-n`，可以设置环境变量，`mqadmin`、`mqbroker` 等工具会自动读取。

#### 🐧 Linux

```bash
# 当前会话生效
export NAMESRV_ADDR=127.0.0.1:9876

# 永久生效（写入 ~/.bashrc 或 ~/.bash_profile）
echo 'export NAMESRV_ADDR=127.0.0.1:9876' >> ~/.bashrc
source ~/.bashrc
```

#### 🪟 Windows

```cmd
set NAMESRV_ADDR=127.0.0.1:9876
```
（如需永久生效，可在“系统属性 → 环境变量”中添加。）

设置后，`mqadmin clusterList` 即可省略 `-n`。

## 4. 功能验证：收发一条测试消息（可选但推荐）

RocketMQ 发行包自带 `tools` 脚本，可用于快速验证消息链路。

#### 🐧 Linux

```bash
cd $ROCKETMQ_HOME

# 终端 A：启动消费者
export NAMESRV_ADDR=127.0.0.1:9876
sh bin/tools.sh org.apache.rocketmq.example.quickstart.Consumer

# 终端 B：启动生产者
export NAMESRV_ADDR=127.0.0.1:9876
sh bin/tools.sh org.apache.rocketmq.example.quickstart.Producer
```

生产者会发送 1000 条消息后退出；消费者终端应持续打印收到的消息。

#### 🪟 Windows

```cmd
cd /d %ROCKETMQ_HOME%\bin

:: 窗口 A：消费者
set NAMESRV_ADDR=127.0.0.1:9876
tools.cmd org.apache.rocketmq.example.quickstart.Consumer

:: 窗口 B：生产者
set NAMESRV_ADDR=127.0.0.1:9876
tools.cmd org.apache.rocketmq.example.quickstart.Producer
```

## 5. RocketMQ Dashboard（Web 可视化管控台）

`mqadmin` 命令行之外，**RocketMQ Dashboard**（原 Console）是最常用的 Web 管控界面。

### 启动方式（取决于你使用的版本形态）

**方式 A：通过 `mqadmin` 内嵌命令（部分 4.x 发行包提供）**

```bash
# Linux
nohup sh bin/mqadmin startConsoleWeb &

# Windows
start mqadmin.cmd startConsoleWeb
```
默认监听 **8080** 端口，浏览器访问 `http://<服务器IP>:8080` 或 `http://localhost:8080`。

**方式 B：独立 `rocketmq-dashboard` jar 包（更常见）**

```bash
java -jar rocketmq-dashboard-*.jar \
  --rocketmq.config.namesrvAddr=127.0.0.1:9876
```
启动后同样访问 `http://localhost:8080`。

> 如果 8080 被占用，可通过 `--server.port=8082` 等参数调整。

## 6. 停止流程（顺序：先 Broker，后 NameServer）

停止时应**先停 Broker，再停 NameServer**，避免 Broker 在 NameServer 消失后不断重试注册而产生大量错误日志。

### 🐧 Linux（推荐 `mqshutdown`）

```bash
cd $ROCKETMQ_HOME

# 停 Broker
sh bin/mqshutdown broker

# 停 NameServer
sh bin/mqshutdown namesrv
```
`mqshutdown` 会向对应进程发送优雅关闭信号。

### 🪟 Windows

```cmd
cd /d %ROCKETMQ_HOME%\bin

mqshutdown.cmd broker
mqshutdown.cmd namesrv
```

如果 `mqshutdown` 因环境问题无法正常关闭，Windows 下可回退到任务管理器结束对应 Java 进程；Linux 下可回退到 `pkill -f mqbroker` / `pkill -f mqnamesrv`（注意这会强制终止，仅在优雅关闭失败时使用）。

## 7. 常用检测/运维命令速查（`mqadmin`）

| 目的              | 命令                                                         |
| ----------------- | ------------------------------------------------------------ |
| 集群概况          | `mqadmin clusterList -n 127.0.0.1:9876`                      |
| Broker 运行状态   | `mqadmin brokerStatus -n 127.0.0.1:9876 -b 127.0.0.1:10911`  |
| Topic 列表        | `mqadmin topicList -n 127.0.0.1:9876`                        |
| Topic 路由        | `mqadmin topicRoute -n 127.0.0.1:9876 -t <TopicName>`        |
| Topic 队列 offset | `mqadmin topicStatus -n 127.0.0.1:9876 -t <TopicName>`       |
| 创建/更新 Topic   | `mqadmin updateTopic -n 127.0.0.1:9876 -c DefaultCluster -t <TopicName>` |
| 删除 Topic        | `mqadmin deleteTopic -n 127.0.0.1:9876 -c DefaultCluster -t <TopicName>` |
| 全部 Topic 统计   | `mqadmin statsAll -n 127.0.0.1:9876`                         |
| 消费进度（全部）  | `mqadmin consumerProgress -n 127.0.0.1:9876`                 |
| 指定消费组进度    | `mqadmin consumerProgress -n 127.0.0.1:9876 -g <GroupName>`  |

> 以上命令在 Linux 下前缀 `sh bin/`，Windows 下前缀 `mqadmin.cmd`。`-n` 可省略（如果已设置 `NAMESRV_ADDR`）。

## 8. 关键注意事项

1. **NameServer 必须先启动**：Broker 进程即使能在没有 NameServer 的情况下“存活”，也无法完成注册，`clusterList` 中看不到它，对客户端不可见。
2. **`clusterList` 能查到 Broker，才算真正就绪**：进程存在、端口监听、日志 `boot success` 都是必要条件，但 `mqadmin clusterList` 的成功输出才是服务可用的最终判据。
3. **Windows 窗口不能关**：`start mqnamesrv.cmd` / `start mqbroker.cmd` 打开的 cmd 窗口如果关闭，对应服务即终止。
4. **日志路径统一**：无论是 Linux 还是 Windows，默认日志都在 `${user.home}/logs/rocketmqlogs/`，排查启动问题时优先看 `namesrv.log` 和 `broker.log` 中的 `boot success` 及异常堆栈。
